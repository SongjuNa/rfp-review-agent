# review-workspace Specification

## Purpose
엔지니어가 위험 조건과 내세울 강점을 원문 위치와 함께 먼저 보고 판단만 하도록, 검토 결과를 한국어 요약 + 원문으로 보여 주는 화면이다 (NFR-08).

## Requirements

### Requirement: 문서 올리기와 실행 상태
화면은 docx를 올려 검토를 시작하고, 실행의 현재 단계와 실패 메시지("처리 실패 — 다시 시도")를 보여 줘야 한다(SHALL).

#### Scenario: 처리 중
- **WHEN** 엔지니어가 파일 1을 올리면
- **THEN** 실행이 시작되고 현재 단계가 보인다

### Requirement: 근거와 함께 보이는 결과
화면은 요구사항(유형 칸 포함), 위험 조건, 적합성 판정, 보증값 후보, 일탈·질의 목록, 제안 포인트를 보여 주고, 각 줄에서 원문 위치와 원문을 볼 수 있어야 한다(SHALL). 팀 가정 값이 들어간 줄에는 "팀 가정"이 보여야 한다(SHALL).

#### Scenario: 적합성 표의 비교 제품
- **WHEN** 엔지니어가 적합성 표를 열면
- **THEN** 각 판정의 비교 제품, 제품값, 여유와 방향이 보이고 비교 제품을 바꿔 볼 수 있다

#### Scenario: 손실 환산 결과
- **WHEN** 엔지니어가 손실 환산 결과를 열면
- **THEN** 계산식, 합계, "팀 가정" 표시가 보인다

### Requirement: 판단 동작
화면은 각 후보에 확정·수정·반려(제안 포인트는 채택·버림·수정)를 사유와 함께 남기게 하고, 결재 상신 창에서 지금 걸리는 승인 기준을 미리 보여 주며 결재자와 상신 의견을 받아야 한다(SHALL). 승인자에게는 상신 의견, 걸린 승인 기준과 누락 점검 결과를 보여 주고, 엔지니어에게는 결정 전 상신 취소 버튼을 보여 줘야 한다(SHALL).

#### Scenario: 승인 화면
- **WHEN** 승인자가 승인 대기 실행을 열면
- **THEN** 상신 의견, 걸린 승인 기준, 일탈 후보 수, 목록에 들어간 수, 빠진 일탈이 보인다

#### Scenario: 결재 상신 창
- **WHEN** 엔지니어가 일탈 후보가 있는 검토에서 결재 상신 창을 열면
- **THEN** 지금 걸리는 기준 AR-01이 보이고, 결재자와 상신 의견을 넣기 전에는 상신 버튼이 눌리지 않는다

### Requirement: 내 할 일 화면
화면은 고른 사용자 역할의 "내 할 일"을 보여 줘야 한다(SHALL). 견적·품질·영업 담당은 전달받은 할 일(유형 또는 제안 포인트 종류, 반복 표시, 원문 위치, 상태)을 읽기만 하고 상태 단추는 없다. 기술 검토 엔지니어는 담당자 확인 중인 검토, 승인자는 자기에게 상신된 승인 대기 검토를 걸린 승인 기준과 함께 본다(SHALL).

#### Scenario: 견적 담당 내 할 일
- **WHEN** 견적 담당 사용자를 고르고 "내 할 일"을 열면
- **THEN** 손실 환산 조항 할 일이 원문 위치, 상태와 함께 보이고 상태 단추는 없다

#### Scenario: 엔지니어·승인자의 내 할 일
- **WHEN** 엔지니어가 "내 할 일"을 열면 담당자 확인 중인 검토가, 승인자가 열면 자기에게 상신된 승인 대기 검토가 보이고
- **THEN** 카드마다 걸린 승인 기준이 보이고 누르면 그 검토가 열린다

#### Scenario: 다른 결재자에게 간 검토
- **WHEN** 승인자 두 명 중 한 명에게만 상신된 검토가 있을 때 다른 승인자가 "내 할 일"을 열면
- **THEN** 그 검토는 보이지 않는다

### Requirement: 앱 틀과 화면 주소
화면은 목업과 같은 왼쪽 메뉴(홈, RFP 관리, 지식 관리, 팀 공유, 설정)와 머리글(메뉴 접기, 현재 위치, 검색, 알림, 사용자)을 모든 화면에 보여 줘야 한다(SHALL). 화면마다 주소가 있어 주소로 바로 열거나 새로 고쳐도 같은 화면과 메뉴 강조가 보여야 한다(SHALL). 메뉴 접기 상태는 브라우저에 기억해야 한다(SHALL).

#### Scenario: 메뉴로 화면 이동
- **WHEN** 엔지니어가 RFP 검토 화면에서 지식 관리 > 제품 관리를 누르면
- **THEN** 주소가 제품 관리 화면 주소로 바뀌고 제품 관리 메뉴가 강조되며 현재 위치에 홈과 제품 관리가 보인다

#### Scenario: 메뉴 접기
- **WHEN** 사용자가 메뉴 접기를 누르고 화면을 새로 고치면
- **THEN** 메뉴는 아이콘만 남은 접힌 상태로 보인다

### Requirement: 머리글 사용자 고르기
로그인이 없으므로 화면은 머리글 사용자 칩에서 사용자를 바꾸게 하고, 고른 사용자의 이름과 역할을 머리글에 보여 주며, 모든 화면의 권한을 그 역할로 정해야 한다(SHALL). 고른 사용자는 브라우저에 기억해야 한다(SHALL).

#### Scenario: 사용자 바꾸기
- **WHEN** 엔지니어로 보던 사용자가 사용자 칩에서 기본 승인자를 고르면
- **THEN** 머리글에 기본 승인자와 승인자 역할이 보이고 새로 고쳐도 유지된다

### Requirement: 예시로 보이는 알림
알림 API가 없는 동안 화면은 머리글 알림을 예시 데이터로 보여 주고 "예시" 표시를 붙여야 한다(SHALL). 예시 알림은 저장하지 않는다.

#### Scenario: 알림은 예시로 보인다
- **WHEN** 사용자가 머리글 알림 단추를 누르면
- **THEN** "예시" 표시가 붙은 알림 목록이 보이고 모두 읽음으로 하면 읽지 않은 수가 0이 된다

### Requirement: 검토 정보 입력과 표시
화면은 검토를 시작할 때 검토 정보(사업명, 검토명, 고객사, 국가, 제출 마감일, 담당 엔지니어)를 넣을 칸을 보여 주고, 검토 목록과 검토 머리글에 검토 번호·검토 정보·마감까지 남은 날(D-day)을 보여 줘야 한다(SHALL). 검토명이 비어 있으면 첫 파일 이름을 대신 보여 준다. 머리글에서 검토 정보를 고칠 수 있어야 한다(SHALL).

#### Scenario: 목록에서 마감 보기
- **WHEN** 마감일이 3일 뒤인 검토가 있는 상태에서 검토 목록을 열면
- **THEN** 그 줄에 검토 번호, 사업명, 검토명, 고객사, 담당 엔지니어, "D-3"과 요구사항·위험·일탈·제안 개수가 보인다

#### Scenario: 검토명이 빈 검토
- **WHEN** 검토 정보 없이 시작한 검토를 목록에서 보면
- **THEN** 검토명 자리에 첫 파일 이름이 보이고 마감 자리는 비어 있다

#### Scenario: 머리글에서 고치기
- **WHEN** 엔지니어가 검토 머리글에서 고객사를 고치고 저장하면
- **THEN** 머리글과 목록에 새 고객사가 보이고 이력 탭에 그 변경이 보인다

### Requirement: 검토 상세 요약 칸과 탭
화면은 처리를 마친 검토 상세의 머리글 아래에 요약 칸 5개(일탈 후보, 질의 후보, 확인 필요 비율과 기준, 보증값 작성, 손실 환산 참고값)와 탭 9개(판정, 문서 읽기 점검, 위험 조건, 손실 환산(참고), 입찰 영향, 상업 조건, 지난 RFP 비교, 제출본, 이력)를 목업 순서대로 보여야 한다(SHALL). 탭은 모두 실제 데이터를 보이고 예시 띠를 붙이지 않는다. 직접 작성할 칸이 있으면 확인 필요 비율 칸에 그 칸을 뺐다는 것과 개수를, 보증값 작성 칸에 직접 작성할 칸 수를 보인다(SHALL).

#### Scenario: 요약 칸
- **WHEN** 일탈 후보가 있는 검토 상세를 열면
- **THEN** 요약 칸에 일탈 후보 수, 질의 후보 수, 확인 필요 비율과 "기준 20 %", 보증값 작성 수, 손실 환산 참고값이 보인다

#### Scenario: 직접 작성할 칸 표시
- **WHEN** 직접 작성할 칸이 3개인 검토 상세를 열면
- **THEN** 확인 필요 비율 칸에 "직접 작성할 칸 3개 뺌", 보증값 작성 칸에 "직접 작성할 칸 3"이 보인다

#### Scenario: 탭으로 내용 바꾸기
- **WHEN** 검토 상세에서 "이력" 탭을 누르면
- **THEN** 이력 표가 보이고 탭 줄에서 이력 탭이 선택된 것으로 보인다

#### Scenario: 예시 탭
- **WHEN** 마지막 예시 탭이던 "지난 RFP 비교" 탭을 누르면
- **THEN** 예시 띠가 보이지 않는다

### Requirement: 판정 표 거르기
화면은 판정 탭에 판정 칩(전체와 판정 값마다, 건수), "확정 안 한 줄만", 검색어, 유형 거르기를 두고 판정 순서로 정렬한 판정 표(판정, 항목 이름·영문, 요구값, 제품값·보증값, 원문 위치)를 페이지로 나눠 보여야 한다(SHALL). 표 아래에 보이는 줄 수와 전체 판정 수를 보인다(SHALL).

#### Scenario: 판정 칩으로 거르기
- **WHEN** 판정 탭에서 "일탈 후보" 칩을 누르면
- **THEN** 표에는 일탈 후보 줄만 보이고 칩의 건수와 표 아래 줄 수가 같다

#### Scenario: 거른 결과가 없음
- **WHEN** 맞는 줄이 없는 검색어를 넣으면
- **THEN** "조건에 맞는 줄이 없습니다"와 필터 지우기가 보인다

### Requirement: 판정 상세 패널
화면은 판정 줄을 누르면 오른쪽 패널에 원문 위치와 원문 문장, 판정 근거, 판정 출처(시스템 제안과 담당자 확정), 그 판정에서 나온 일탈·질의 목록 문장, 판정 바꾸기를 보여야 한다(SHALL). 판정을 바꾸려면 사유가 있어야 하고(MUST), 담당자 확인 단계에서만 바꾸거나 확정할 수 있다(SHALL).

#### Scenario: 줄을 눌러 원문 보기
- **WHEN** 판정 표에서 일탈 후보 줄을 누르면
- **THEN** 패널에 원문 위치, 원문 문장, 판정 근거, "시스템 제안 일탈 후보"와 "아직 확정 안 함"이 보인다

#### Scenario: 사유 없이 판정 바꾸기
- **WHEN** 패널에서 새 판정을 고르고 사유를 비우면
- **THEN** 적용 단추가 눌리지 않고, 사유를 넣고 적용하면 표의 판정과 담당자 확정이 바뀐다

### Requirement: 위험 조건 탭
시스템은 위험 조건 탭 머리에 닫지 않은 위험 조건 수를 종류별로 보이고, 위험 조건마다 상태, 종류와 표현 또는 항목 이름·값, 설명, 원문 위치를 한 줄로 보여야 한다(SHALL). 문제 없음으로 닫은 줄은 흐리게 맨 아래에 두고 닫은 사유와 누가·언제 닫았는지 보인다. 엔지니어는 담당자 확인 단계에서 후보를 위험으로 확정하거나, 사유를 적어 문제 없음으로 닫을 수 있다(SHALL).

#### Scenario: 위험 조건 건수
- **WHEN** 포괄 조항·값 불일치·범위 모호 후보가 하나씩 있는 실행의 위험 조건 탭을 열면
- **THEN** 머리에 "포괄 조항 1 · 값 불일치 1 · 범위 모호 1"이 보이고, 줄 3개에 "후보" 배지와 원문 위치가 보인다

#### Scenario: 문제 없음으로 닫기
- **WHEN** 엔지니어가 값 불일치 후보에서 문제 없음을 누르고 사유를 적어 닫으면
- **THEN** 그 줄은 "문제 없음" 배지로 흐리게 맨 아래에 가고, 사유와 닫은 사람이 보이며, 머리의 값 불일치 수가 0이 된다

#### Scenario: 사유 없이 닫기
- **WHEN** 문제 없음 사유 칸이 비어 있으면
- **THEN** 닫기 단추가 눌리지 않는다

#### Scenario: 위험으로 확정
- **WHEN** 엔지니어가 포괄 조항 후보를 위험으로 확정하면
- **THEN** 그 줄의 배지가 "확정"이 되고 확정한 사람이 보인다

### Requirement: 손실 환산 탭
시스템은 손실 환산 탭에 고객 손실 환산 조항이 있을 때만 계산한 참고값이라는 안내, 단가 행 위치, 무부하·부하·보조마다 단가·손실값·가산액, 가산액 합계를 보여야 한다(SHALL). 엔지니어는 담당자 확인 단계에서 손실값을 넣어 다시 계산할 수 있고, 직접 넣은 값이 들어간 결과에는 "팀 가정"을 보인다(SHALL). 조항이 없으면 계산하지 않았다고 알린다.

#### Scenario: 손실 환산 표
- **WHEN** 손실 환산 단가 행이 있고 비교 제품이 없는 실행의 손실 환산 탭을 열면
- **THEN** 무부하·부하·보조 줄에 단가가 보이고, 손실값 칸은 비어 있으며, 가산액 합계는 "—"이다

#### Scenario: 손실값 넣어 다시 계산
- **WHEN** 엔지니어가 세 손실값을 60·300·8 kW로 넣으면
- **THEN** 줄마다 가산액과 합계 $1,240,400이 보이고 "팀 가정" 표시가 붙는다

#### Scenario: 조항 없는 RFP
- **WHEN** 손실 환산 조항이 없는 실행의 손실 환산 탭을 열면
- **THEN** "이 RFP에는 손실 환산 조항이 없어 계산하지 않았습니다."가 보인다

### Requirement: 입찰 영향 탭
시스템은 입찰 영향 탭에 유리한 점으로 제안 포인트(근거, 상태, 문장, 종류와 원문 위치, 팀 가정·숫자 불일치 표시)를, 불리한 점으로 일탈 후보와 질의 후보 판정(항목 이름 + "미달" 또는 "값 불명확", 대응 문장)을 보여야 한다(SHALL). 엔지니어는 담당자 확인 단계에서 제안 포인트를 채택하거나 사유를 적어 버릴 수 있다(SHALL). 채택·버림은 단추로 보이고, 누르면 그 포인트에 결과 알림(채택은 전달받는 담당, 버림은 사유)을 보이며, 채택한 줄과 버린 줄을 색으로 구분해야 한다(SHALL). [제안] 불리한 점이 없으면 "불리한 점이 없습니다."를 보인다.

#### Scenario: 제안 포인트 채택
- **WHEN** 엔지니어가 후보 상태의 제안 포인트에서 채택을 누르면
- **THEN** 그 포인트 채택 요청이 가고 상태가 "채택"으로 바뀐다

#### Scenario: 채택 알림
- **WHEN** 엔지니어가 손실 환산 제안 포인트를 채택하면
- **THEN** 그 포인트에 "채택했습니다. 영업·견적 담당에게 협조 요청으로 전달합니다." 알림이 보이고 줄이 채택 색으로 바뀐다

#### Scenario: 버림 알림
- **WHEN** 엔지니어가 사유를 적고 제안 포인트를 버리면
- **THEN** 그 포인트에 "버렸습니다. 사유:"와 적은 사유가 보이고 줄이 흐리게 바뀐다

#### Scenario: 사유 없이 버리기
- **WHEN** 제안 포인트의 버림을 누르고 사유 칸이 비어 있으면
- **THEN** 버리기 단추가 눌리지 않는다

#### Scenario: 불리한 점 목록
- **WHEN** 일탈 후보 1건과 질의 후보가 있는 실행의 입찰 영향 탭을 열면
- **THEN** 불리한 점에 일탈 후보는 "미달", 질의 후보는 "값 불명확" 줄로 대응 문장과 함께 보인다

### Requirement: 머리글 비교 제품 고르기
시스템은 검토 상세 머리글 아래에 비교 제품이 있는 설비 묶음마다 한 줄로 묶음 이름과 후보 제품 단추를 보이고 지금 비교 제품을 표시해야 한다(SHALL). 후보 단추가 많으면 줄을 바꿔 화면 폭을 넘지 않는다. 묶음이 4개보다 많으면 처음에는 설비 수와 지금 제품을 요약한 줄만 보이고 누르면 펼친다. 엔지니어가 담당자 확인 단계에서 다른 제품을 누르면 그 묶음을 다시 판정하고 탭 본문을 새로 불러온다(SHALL). 다시 판정하는 동안에는 화면 가운데에 "다시 판정 중…"을 크게 보이고 다른 단추가 눌리지 않게 해야 한다(SHALL). [제안]

#### Scenario: 비교 제품 보기
- **WHEN** 판정이 끝난 검토 상세를 열면
- **THEN** 머리글 아래에 "TS-115-GIS" 묶음과 지금 제품이 눌린 단추로 보인다

#### Scenario: 비교 제품 바꾸기
- **WHEN** 후보가 둘인 설비 묶음에서 엔지니어가 다른 제품을 누르면
- **THEN** 그 제품으로 바꾸는 요청이 가고, 바뀐 제품이 눌린 단추로 보인다

#### Scenario: 설비 묶음이 많은 비교 제품
- **WHEN** 설비 묶음이 12개이고 그중 하나의 후보가 14개인 검토 상세를 열면
- **THEN** "설비 12개" 요약만 보이고, 펼치면 묶음 12줄이 보이며 후보 14개 단추가 화면 폭을 넘지 않는다

#### Scenario: 다시 판정 중 화면 막기
- **WHEN** 엔지니어가 다른 비교 제품을 눌러 다시 판정이 끝나기 전이면
- **THEN** 화면 가운데에 "다시 판정 중…"과 묶음 이름·바꾼 제품이 보이고, 탭과 다른 단추를 눌러도 동작하지 않으며, 다시 판정이 끝나면 안내가 사라진다

### Requirement: 이력 탭
시스템은 이력 탭에 수정 이력을 새것부터 시각, 사람, 무엇을 어떻게 바꿨는지 한 줄 문장, 사유(결재·상신은 의견)로 보이고, 맨 아래에 시스템이 판정을 만든 줄을 보여야 한다(SHALL). 문장은 기록된 값만 쓴다.

#### Scenario: 판정 바꾼 이력
- **WHEN** 엔지니어가 판정을 일탈 후보로 바꾼 뒤 이력 탭을 열면
- **THEN** 맨 위 줄에 엔지니어 이름, "판정 "<항목 이름>" <이전 판정> → 일탈 후보", "사유: <사유>"가 보이고 맨 아래 줄은 "시스템 · 판정 n줄 생성"이다

#### Scenario: 위험 조건 닫은 이력
- **WHEN** 위험 조건을 문제 없음으로 닫은 뒤 이력 탭을 열면
- **THEN** "위험 조건 "<표현>" 문제 없음으로 닫음"과 닫은 사유가 보인다

### Requirement: 목록 초안 내려받기와 문장 고치기
시스템은 판정 탭의 "일탈 목록 초안"·"질의서 초안" 단추를 누르면 진행 화면을 보인 뒤 Word 파일을 내려받고 "<파일 이름>를 만들었습니다." 알림을 보여야 한다(SHALL). 일탈·질의 문장은 판정 패널·판정 상세 창(위험 조건에서 나온 문장은 위험 조건 줄을 펼친 곳)에서 보이고, 엔지니어는 담당자 확인 단계에서 문장을 확정하거나, 사유를 적어 고치거나 목록에서 뺄 수 있다(SHALL).

#### Scenario: 일탈 목록 초안 내려받기
- **WHEN** 엔지니어가 판정 탭에서 "일탈 목록 초안"을 누르면
- **THEN** 진행 화면이 보였다가 "일탈 목록 초안_<검토 번호>.docx" 파일이 내려받아지고 만들었다는 알림이 보인다

#### Scenario: 사유 적어 문장 고치기
- **WHEN** 엔지니어가 판정 패널의 질의 문장을 고치면
- **THEN** 사유 칸이 나오고 사유가 비면 문장 저장 단추가 눌리지 않으며, 사유를 적어 저장하면 고친 문장이 "확정" 상태로 남는다

### Requirement: 문서 읽기 점검 탭
시스템은 문서 읽기 점검 탭에 종류별 건수(표·그림·단위·위치), 확인 안 한 건수 표시, 안내 문장과 점검 표(종류와 무엇, 위치·파일·문제·할 일, 확인 단추)를 보여야 한다(SHALL). 엔지니어가 "직접 확인함"을 누르면 "확인함"과 사람·시각, "되돌리기"가 보이고 줄이 흐려진다. 탭 이름 옆에는 확인 안 한 건수를 보인다. 점검 줄이 하나도 없으면 빈 표 대신 "모든 문서를 끝까지 읽었습니다"와 살핀 것(표 칸 역할·그림·단위·절 번호)을 보이고, 머리 표시는 "읽지 못한 곳 없음"이다. [제안]

#### Scenario: 점검 줄 확인
- **WHEN** 엔지니어가 문서 읽기 점검 탭에서 한 줄의 "직접 확인함"을 누르면
- **THEN** 그 줄에 "확인함"과 엔지니어 이름이 보이고, 머리 표시와 탭 이름 옆 건수가 하나 줄며, 이력 탭에 "문서 읽기 점검 확인" 줄이 생긴다

#### Scenario: 점검 확인 되돌리기
- **WHEN** 확인한 줄의 "되돌리기"를 누르면
- **THEN** 다시 "직접 확인함" 단추가 보이고 확인 안 한 건수가 늘어난다

#### Scenario: 고칠 수 없을 때 확인 단추
- **WHEN** 엔지니어가 아닌 사용자가 문서 읽기 점검 탭을 열면
- **THEN** "직접 확인함" 단추가 눌리지 않고 이유가 안내된다

#### Scenario: 읽지 못한 곳이 없는 검토
- **WHEN** 읽지 못한 곳이 없는 합성 데이터시트 검토의 문서 읽기 점검 탭을 열면
- **THEN** 점검 표 없이 "모든 문서를 끝까지 읽었습니다"와 "직접 확인할 곳이 없습니다"가 보이고, 머리 표시는 "읽지 못한 곳 없음", 탭 이름 옆에는 숫자가 없다

### Requirement: 상신 전 확인의 문서 읽기 점검
시스템은 결재 상신 창의 상신 전 확인 목록에 문서 읽기 점검 줄을 넣어야 한다(SHALL). 확인 안 한 점검이 있으면 "문서 읽기 점검 미확인 n건"(주의), 없으면 "문서 읽기 점검 모두 확인"을 보인다. 미확인이 남아도 상신할 수 있다.

#### Scenario: 상신 창의 점검 미확인
- **WHEN** 확인 안 한 점검 줄이 있는 실행에서 결재 상신 창을 열면
- **THEN** 상신 전 확인에 "문서 읽기 점검 미확인 n건"이 주의 표시로 보인다

### Requirement: 제출본 탭
시스템은 제출본 탭에 승인된 실행의 제출본을 버전(v1), 확정 시각(승인 시각), 결재자, 판정 줄 수, 일탈·질의 후보 수, 첨부, 상태("현재 제출본")로 보여야 한다(SHALL). 승인된 실행에는 "인계 패키지 내려받기"와 엔지니어용 "영업에 넘기기"를 두고, 마지막으로 넘긴 시각·받는 주소 또는 "주소 없음"·"발송 실패"를 보인다(`add-submission-package`). 승인 전이면 제출본이 없다는 안내를 보인다. 승인된 실행은 판정을 고칠 수 없으므로 승인 시점의 판정이 제출본이다. 머리 단추는 승인된 실행에서 "제출본 v1 확정"으로 보인다.

#### Scenario: 승인된 실행의 제출본
- **WHEN** 승인자가 승인한 실행의 제출본 탭을 열면
- **THEN** v1 줄에 결재자 이름, 판정 줄 수, 일탈·질의 후보 수와 "현재 제출본"이 보이고, 머리 단추는 "제출본 v1 확정"이다

#### Scenario: 승인 전 제출본 없음
- **WHEN** 담당자 확인 단계인 실행의 제출본 탭을 열면
- **THEN** "아직 확정된 제출본이 없습니다"로 시작하는 안내가 보인다

#### Scenario: 인계 패키지 영업에 넘기기
- **WHEN** 엔지니어가 승인된 실행의 제출본 탭에서 "영업에 넘기기"를 누르면
- **THEN** "영업 담당(주소)에게 인계 패키지를 보냈습니다" 알림이 보이고 탭에 넘긴 시각이 보인다

### Requirement: 처리 상태 화면
시스템은 처리 중인 검토 상세에 로고, 진행 막대와 백분율, 지금 단계 문장(찾은 문서·요구사항 수 포함)을 보여야 한다(SHALL). 문서 읽기 단계는 세부 일과 AI 일의 처리 줄 수(예: "AI로 유형 붙이는 중 480 / 3,397줄")를 함께 보이고, 백분율은 단계 순서와 세부 진행으로 센다(문서 읽기 단계가 막대 대부분). 지난 시간과 예상 시간 안내를 보이고, 마지막 진행이 10분 넘게 없으면 멈췄을 수 있다고 알린다. "분석 취소" 단추를 누르고 한 번 더 확인하면 취소를 요청하고, 처리가 멈추면 분석 실패 화면으로 바뀐다. 처리가 끝나면 다시 묻지 않아도 검토 상세(탭과 요약 칸)로 바뀐다. [제안]

#### Scenario: 처리 중인 검토
- **WHEN** 위험 조건 찾기 단계를 처리하는 중인 검토 상세를 열면
- **THEN** 진행 막대의 값이 0보다 크고 100보다 작으며 "위험 조건 찾는 중"이 보이고, 처리가 끝나면 판정 탭이 보인다

#### Scenario: 유형 붙이기 진행
- **WHEN** 문서 읽기 단계에서 AI 유형 붙이기 480 / 3,397줄을 처리하는 중인 검토 상세를 열면
- **THEN** "AI로 유형 붙이는 중 480 / 3,397줄"과 지난 시간이 보이고, 진행 막대 값은 같은 단계의 0줄일 때보다 크다

#### Scenario: 오래 진행이 없음
- **WHEN** 마지막 진행 시각이 11분 전인 처리 중 검토 상세를 열면
- **THEN** "10분 넘게 진행이 없습니다" 안내가 보인다

#### Scenario: 처리 중 분석 취소
- **WHEN** 처리 중인 검토 상세에서 "분석 취소"를 누르고 확인 단추를 누르면
- **THEN** 취소 요청이 가고 "취소하는 중" 안내가 보이며, 처리가 멈추면 분석 실패 화면에 "취소했습니다"가 보인다

### Requirement: 분석 실패 화면
시스템은 처리에 실패한 검토 상세에 멈춘 단계와 오류 문장, 다섯 묶음 진행 상황(끝남·멈춤·대기), 지금 볼 수 있는 결과 수, 문서 목록과 읽은 상태, 처리 기록, 복사할 수 있는 문의용 정보를 보여야 한다(SHALL). 다른 실패한 검토가 있으면 그 검토로 가는 연결을 보인다. 계속하는 방법 가운데 "다시 시도"는 검토를 다시 처리하게 하고 처리 상태 화면으로 바꾼다. 나머지 방법은 예시 영역으로 보이고 눌러도 처리하지 않는다. 사람이 취소한 검토는 "○○ 단계에서 취소했습니다"를 보인다.

#### Scenario: 분석 실패 상세
- **WHEN** 위험 조건 찾기 단계에서 실패한 검토 상세를 열면
- **THEN** "위험 조건 찾기 단계에서 멈췄습니다"와 오류 문장이 보이고, 진행 상황은 문서 읽기 끝남, 위험 조건 찾기 멈춤, 나머지 대기이며, 문서 목록에 올린 파일 이름이 보인다

#### Scenario: 계속하는 방법 예시
- **WHEN** 실패 화면에서 "남은 부분은 직접 확인"을 고르고 실행 단추를 누르면
- **THEN** 예시 띠가 보이는 영역이고 "예시 화면이라 처리하지 않았습니다" 알림만 보이며 검토 단계는 그대로다

#### Scenario: 실패 화면에서 다시 시도
- **WHEN** 취소한 검토의 실패 화면에서 "다시 시도"를 고른 채 실행 단추를 누르면
- **THEN** 다시 시도 요청이 가고 화면이 처리 상태 또는 검토 상세로 바뀐다

### Requirement: 협조 요청 현황 화면
시스템은 협조 요청 화면에 수신 부서 탭(견적·품질·영업 담당, 미분류), 안 보냄·회신 대기·24시간 넘게 회신 없음·회신 받음 수, 요청 표(상태, 요구사항과 검토 번호·원문 위치, 보낸 주소, 보낸 일시, 발송 실패 표시)를 보여야 한다(SHALL). 요청 항목은 유형별로 보낸 할 일(FR-11)이다. 발송 실패하거나 판정이 없어 아직 안 보낸 요청에는 "보내기" 단추가 있다. 줄을 누르면 요청 내용, 원문, 회신 요지, 진행(만듦 → 메일 보냄 → 회신 받음)을 보이는 창이 열리고, 엔지니어는 그 창에서 회신 요지를 적고 "회신 받음"을 표시한다. [결정] 메일은 시스템이 보내고, 재요청 자동 알림은 없으며, 요청하기는 예시 창이다.

#### Scenario: 수신 부서별 요청 현황
- **WHEN** 엔지니어가 협조 요청 화면에서 품질 담당 탭을 고르면
- **THEN** 형식시험 성적서 요청 줄이 "안 보냄" 또는 "메일 보냄"으로 검토 번호, 파일 이름이 든 원문 위치와 함께 보이고, 요약 줄에 상태별 수가 보인다

#### Scenario: 24시간 넘게 미확인
- **WHEN** 메일을 보낸 지 24시간이 넘도록 회신 받음이 아닌 요청이 있으면
- **THEN** 그 줄의 상태가 "24시간 넘게 회신 없음"이고 상세 창 진행에 "다시 연락 필요"가 보인다

#### Scenario: 받는 담당자의 확인
- **WHEN** 엔지니어가 메일 보냄인 요청의 상세 창에서 회신 요지를 적고 "회신 받음"을 누르면
- **THEN** 그 줄은 "회신 받음"으로 흐려지고, 다시 열면 회신 요지와 진행의 "회신 받음" 단계가 보인다

#### Scenario: 요청하기 예시
- **WHEN** 엔지니어가 "요청하기" 창에 요구사항과 요청 내용을 적고 "요청 보내기"를 누르면
- **THEN** 예시 띠가 보이는 창이고 "예시 화면이라 보내지 않았습니다" 알림만 보이며 요청 항목 수는 그대로다

### Requirement: 홈 화면
시스템은 홈에 내 업무 네 칸(내가 처리할 건, 결재 대기, 3일 내 마감, 마감 경과)과 내 검토 카드를 단계 열(분석 중, 판정 확인, 협조 대기, 결재 대기, 제출 준비) 또는 사업별로 보여야 한다(SHALL). 엔지니어는 자기가 담당인 검토, 다른 역할은 모든 검토를 본다. 담당자 확인 단계에서 미확인 협조 요청이 남은 검토는 "협조 대기" 열이다. 내 업무 칸을 누르면 그 조건이 아닌 카드를 흐리게 한다. 처리에 실패한 검토가 있으면 위에 알림을 보인다. 팀 업무는 사용자마다 지금 하는 일을 보이고, 공지·시스템 공지·자료실·행사는 예시 영역이다. [결정] 판정 기준 변경 알림과 재시도는 API가 없어 만들지 않는다.

#### Scenario: 내 업무와 단계별 카드
- **WHEN** 엔지니어가 오늘 마감이고 품질 담당 협조 요청이 남은 자기 검토가 있는 상태로 홈을 열면
- **THEN** 그 검토 카드가 "협조 대기" 열에 검토 번호, 검토명, D-Day, 협조 미확인 수와 함께 보이고, "3일 내 마감" 칸 수가 0이 아니다

#### Scenario: 내 업무 칸으로 강조
- **WHEN** 홈에서 "결재 대기" 칸을 누르면
- **THEN** "결재 대기" 필터 칩이 보이고 결재 대기가 아닌 카드는 흐려지며, 칩을 누르면 다시 보통으로 보인다

#### Scenario: 사업별 보기
- **WHEN** 홈에서 "사업별"을 고르면
- **THEN** 카드가 사업 이름 아래로 모이고 카드마다 단계 칩이 보인다

#### Scenario: 분석 실패 알림
- **WHEN** 엔지니어의 검토가 위험 조건 찾기 단계에서 실패한 상태로 홈을 열면
- **THEN** "<검토 번호> <제목> 분석이 멈췄습니다"와 오류 문장, 멈춘 단계가 든 알림과 검토 상세로 가는 "오류 내용 보기"가 보이고, 재시도는 잠겨 있으며, 닫으면 알림이 사라진다

#### Scenario: 팀 공유와 행사 예시
- **WHEN** 홈의 팀 공유를 보면
- **THEN** 팀 업무에 사용자마다 하는 일(승인자는 결재, 담당자는 협조 요청)이 보이고, 공지사항 탭과 행사 영역은 예시 띠와 함께 열고 넘길 수 있다

### Requirement: 제품표 화면
화면은 제품표를 제품군 탭과 검색으로 보여 주고, 빈 칸과 팀 가정 값을 구분해 표시하며, 제품을 고르면 전체 칸·값의 출처·판정에 쓰인 곳·제안 포인트·현장 이력을 보여 줘야 한다(SHALL). 두 제품을 골라 칸을 나란히 비교할 수 있어야 한다(SHALL). "내보내기"를 누르면 지금 거르기대로 제품표 엑셀을 내려받아야 한다(SHALL). 고치기 동작과 엑셀 가져오기는 두지 않는다.

#### Scenario: 제품 상세
- **WHEN** 엔지니어가 제품표에서 판정에 쓰인 제품을 누르면
- **THEN** 오른쪽에 그 제품의 칸, 출처, "판정에 쓰임 n"과 실행별 줄이 보이고 줄을 누르면 그 검토가 열린다

#### Scenario: 두 제품 비교
- **WHEN** 엔지니어가 두 제품을 골라 비교를 누르면
- **THEN** 두 제품의 같은 칸이 한 줄씩 나란히 보이고 빈 칸은 "비어 있음"으로 보인다

#### Scenario: 제품표 내보내기
- **WHEN** 엔지니어가 GIS 탭을 고르고 "내보내기"를 누르면
- **THEN** 엑셀 파일을 내려받고 "제품표_GIS.xlsx 를 내려받았습니다."가 보인다

### Requirement: 판정 규칙 화면
화면은 비교 방향, 위험 표현, 항목 이름, 문서 종류 사전을 탭으로 보여 주고, 줄마다 쓴 횟수(문서 종류는 분류한 문서 수)를 보여 주며 검색할 수 있어야 한다(SHALL). 엔지니어와 승인자에게는 탭마다 "규칙 추가", 줄마다 수정·삭제 단추와 사유를 받는 입력 창을 보이고, 저장하면 표와 "마지막 수정", 펼친 줄의 "수정 이력"을 새로 보여야 한다(SHALL). 다른 역할에게는 단추를 꺼 둔다.

#### Scenario: 규칙 검색
- **WHEN** 엔지니어가 비교 방향 탭에서 "정격 전류"를 검색하면
- **THEN** 그 항목의 규칙 줄만 방향, 시간 조건, 쓴 판정 수와 함께 보인다

#### Scenario: 문서 종류 규칙 탭
- **WHEN** 엔지니어가 판정 규칙 화면에서 문서 종류 탭을 누르고 "bidding"을 검색하면
- **THEN** 입찰 서식 줄만 파일 이름 표현, 첫 장 표현, 순서, 분류한 문서 수와 함께 보인다

#### Scenario: 화면에서 규칙 추가
- **WHEN** 엔지니어가 위험 표현 탭에서 "규칙 추가"를 눌러 표현·종류·조건·사유를 넣고 저장하면
- **THEN** 표에 새 줄이 보이고 "마지막 수정"이 그 엔지니어와 시각으로 바뀐다

#### Scenario: 화면에서 규칙 수정과 이력
- **WHEN** 엔지니어가 문서 종류 줄의 수정 단추로 표현을 고치고 사유를 넣어 저장한 뒤 그 줄을 펼치면
- **THEN** 수정 이력에 바뀌기 전·후 표현, 사유, 고친 사람이 보인다

#### Scenario: 화면에서 규칙 삭제
- **WHEN** 엔지니어가 위험 표현 줄의 삭제 단추를 누르고 사유를 넣어 확인하면
- **THEN** 그 줄이 표에서 사라진다

#### Scenario: 고칠 수 없는 역할
- **WHEN** 견적 담당이 판정 규칙 화면을 열면
- **THEN** 추가·수정·삭제 단추가 꺼져 있고 "엔지니어·승인자만 고칠 수 있습니다"가 보인다

### Requirement: 판정 탭 한꺼번에 확정
검토 상세 판정 탭은 줄 고르기 칸과, 고른 줄이 있으면 "n줄 선택 · 제안대로 확정" 띠를, 고른 줄이 없고 확정하지 않은 준수 판정이 있으면 "준수 n줄 모두 확정" 띠를 보여야 한다(SHALL). 담당자 확인 단계가 아니면 두 띠를 보이지 않는다.

#### Scenario: 고른 줄 확정
- **WHEN** 엔지니어가 판정 2줄을 고르고 "제안대로 확정"을 누르면
- **THEN** 두 줄이 확정됨으로 바뀌고 "판정 2줄을 제안대로 확정했습니다." 알림이 보인다

#### Scenario: 준수 모두 확정
- **WHEN** 확정하지 않은 준수 판정이 있는 검토에서 "준수 n줄 모두 확정"을 누르면
- **THEN** 띠가 사라지고 준수 판정은 모두 확정됨이다

### Requirement: TBE 준수표 화면
시스템은 검토 상세 머리의 "TBE 준수표" 단추로 TBE 준수표 화면을 열고, 판정 기준·넣을 줄·항목 언어 선택, 요약(넣는 줄, 준수, 일탈, 질의, 확인 필요, 그중 후보, 위치 없어 뺀 줄), 미리보기 표, "엑셀 내려받기"를 보여야 한다(SHALL). 판정 기준 "제출본 v1"은 승인된 실행에서만 고를 수 있다. 제출본 탭의 "이 판정으로 TBE 준수표 받기"도 이 화면을 연다.

#### Scenario: 넣을 줄 바꾸기
- **WHEN** 엔지니어가 TBE 준수표 화면에서 "확정한 줄만"을 고르면
- **THEN** 미리보기와 넣는 줄 수가 확정한 줄만으로 바뀌고 파일 이름이 "…_확정만.xlsx"가 된다

#### Scenario: 엑셀 내려받기
- **WHEN** "엑셀 내려받기"를 누르면
- **THEN** .xlsx 파일이 내려받아지고 "…를 내려받았습니다 (n줄)." 알림이 보인다

### Requirement: 데이터시트 채우기 화면
시스템은 검토 상세 머리의 "데이터시트 채우기" 단추로 데이터시트 화면을 열고, 데이터시트 고르기, 요약(제출할 칸, 채움 · 확정, 채움 · 후보, 확인 필요), 채움 막대, 보기 거르기(전체 / 후보 / 확인 필요 / 확정), 표, "엑셀 내려받기"를 보여야 한다(SHALL). 후보 줄의 "확정"은 담당자 확인 단계의 엔지니어만 누를 수 있고, 누르면 그 칸이 확정으로 바뀐다. "영업에 넘기기"는 엔지니어에게만 열리고, 후보 칸이 남아 있으면 "후보 n칸을 먼저 확정" 안내와 함께 막는다. 넘기면 "영업 담당에게 넘겼습니다. 확인 필요 n칸은 비운 채로 넘어갑니다." 알림이 보이고, 넘긴 표는 단추가 "다시 넘기기"로 바뀌며 넘긴 시각을 보인다(`add-submission-package`).

#### Scenario: 칸 확정
- **WHEN** 엔지니어가 후보 줄의 "확정"을 누르면
- **THEN** 그 줄 상태가 확정이 되고 "칸 n … 값을 확정했습니다." 알림이 보이며 채움 · 확정 수가 1 늘어난다

#### Scenario: 확인 필요만 보기
- **WHEN** 보기에서 "확인 필요"를 고르면
- **THEN** 채운 값이 빈 줄만 보인다

#### Scenario: 데이터시트 영업에 넘기기
- **WHEN** 엔지니어가 후보 칸이 없는 데이터시트에서 "영업에 넘기기"를 누르면
- **THEN** "영업 담당에게 넘겼습니다" 알림이 보이고 단추가 "다시 넘기기"로 바뀐다

#### Scenario: 후보가 남아 넘기기 막힘
- **WHEN** 후보 칸이 남은 데이터시트를 열면
- **THEN** "영업에 넘기기"가 막혀 있고 "후보 n칸을 먼저 확정" 안내가 보인다

### Requirement: 예시 화면
시스템은 백엔드 기능이 없는 메뉴 화면(로그인, 입찰 이력·상세, 표준 문구, 팀 현황, 공지사항, 시스템 공지, 자료실, 설정)을 목업 레이아웃 그대로 고정 예시 데이터로 보여야 하고(SHALL), 로그인을 뺀 화면은 맨 위에 "예시 화면 · 실제 데이터와 연결되지 않음" 띠를 보여야 한다(SHALL). 로그인은 앱 틀 밖이라 목업처럼 띠를 두지 않는다. 예시 화면의 동작은 저장하지 않아야 하며(MUST NOT) 다시 열면 처음 상태다. 입찰 금액과 가격 평가는 가린다. 사업 현황·상세(`add-project-status`)와 정답지·채점(`add-evaluation`)은 실제 화면이다.

#### Scenario: 예시 띠
- **WHEN** 왼쪽 메뉴에서 "입찰 이력"을 열면
- **THEN** 목업과 같은 입찰 이력 표와 "예시 화면 · 실제 데이터와 연결되지 않음" 띠가 보이고 서버의 검토 API를 부르지 않는다

#### Scenario: 저장하지 않음
- **WHEN** 예시 화면에서 값을 바꾸는 동작(예: 공지 읽음, 설정 바꾸기)을 하고 화면을 다시 열면
- **THEN** 처음 상태로 보인다

#### Scenario: 금액 가림
- **WHEN** 입찰 이력이나 입찰 상세를 열면
- **THEN** 금액 칸은 숫자 대신 "영업 권한 필요"로 보인다

### Requirement: 처리 중 목록 새로고침
검토 목록과 홈은 처리 중인 검토가 하나라도 있으면 사용자가 새로고침하지 않아도 몇 초마다 실행 목록을 다시 불러와야 하고(SHALL), 처리 중 표시에 지금 단계와 백분율을 함께 보여야 한다(SHALL). 처리 중인 검토가 없으면 다시 부르지 않는다.

#### Scenario: 목록이 저절로 바뀜
- **WHEN** 처리 중인 검토가 있는 검토 목록을 열어 두고 그 검토의 처리가 끝나면
- **THEN** 새로고침하지 않아도 그 줄의 상태가 "처리 중"에서 담당자 확인 상태로 바뀐다

### Requirement: 긴 목록 페이지 번호
시스템은 표 아래 페이지 번호가 9쪽보다 많으면 처음 쪽, 끝 쪽, 지금 쪽 앞뒤 2쪽만 단추로 보이고 나머지는 "…"로 줄여야 한다(SHALL). 이전·다음 단추와 한 페이지 개수 고르기는 항상 화면 안에 보인다.

#### Scenario: 페이지가 많은 목록
- **WHEN** 판정 1,537줄을 10줄씩 보는 판정 탭에서 마지막 쪽 154를 누르면
- **THEN** 번호 단추는 9개 이하이고 154쪽 판정을 불러오며, 이전 단추를 누르면 153쪽이 된다

### Requirement: 검토 상세 문서 표
시스템은 검토 상세 머리글에 판정 대상 문서의 묶음을 "묶음 A·B"처럼 보이고, 판정 대상 문서가 없으면 "판정 문서 없음"을 눈에 띄게 보여야 한다(SHALL). 머리글의 "문서 n개"를 누르면 문서마다 파일 번호, 파일 이름, 문서 종류, 분류 방법(규칙·AI·사람), 묶음, 판정 대상 여부, 요구사항 수, 확인 필요 표시를 보이는 표가 열려야 한다(SHALL). 판정하지 않는 문서는 "판정 안 함"과 이유를 강조해 보여야 한다(SHALL). 이미 분석한 문서의 묶음은 화면에서 고치지 않는다. 엔지니어가 담당자 확인 단계 검토를 열면 창 아래 "문서 추가"에서 docx를 골라 분류 추천을 보고 묶음·문서 종류를 고른 뒤 "추가하고 다시 분석"을 누를 수 있어야 한다(SHALL). 누르면 창이 닫히고 검토는 처리 중 화면으로 바뀐다. 다른 사용자나 다른 단계에서는 "문서 추가"를 보이지 않는다. [제안]

#### Scenario: 판정 묶음 보기
- **WHEN** 묶음 A 문서 하나로 판정을 마친 검토 상세를 열면
- **THEN** 머리글에 "문서 1개"와 "묶음 A"가 보인다

#### Scenario: 문서 표 열기
- **WHEN** 엔지니어가 머리글의 "문서 1개"를 누르면
- **THEN** 창이 열리고 그 문서의 파일 이름, 문서 종류, 분류 방법(규칙 또는 AI), 묶음 A, 판정 대상, 요구사항 수가 보인다

#### Scenario: 판정하지 않는 문서
- **WHEN** 문서 목록에 없어 묶음 C로 분류된 문서만 있는 검토 상세를 열면
- **THEN** 머리글에 "판정 문서 없음"이 보이고, 문서 표에서 그 문서는 "판정 안 함"과 이유, "확인 필요"가 강조되어 보인다

#### Scenario: 문서 추가하고 다시 분석
- **WHEN** 엔지니어가 판정 1줄을 확정한 검토의 문서 표에서 docx 하나를 골라 "추가하고 다시 분석"을 누르면
- **THEN** 분석이 끝난 뒤 머리글에 "문서 2개"가 보이고, 확정한 그 줄은 "확정" 그대로이며, 이력에 "문서 추가"와 파일 이름이 보인다

#### Scenario: 승인자에게는 문서 추가 없음
- **WHEN** 승인자가 담당자 확인 단계 검토의 문서 표를 열면
- **THEN** "문서 추가" 칸이 보이지 않는다

### Requirement: 검토 등록 문서 분류 확인
화면은 검토 등록에서 문서를 고르면 분석 전 분류 추천을 불러와 문서 표의 문서 종류·묶음·언어 칸에 채우고, 판정 대상 여부와 추천 이유를 보여야 한다(SHALL). 사람은 문서마다 묶음(A~D)과 문서 종류를 고를 수 있고, 등록하고 분석을 시작하면 고른 값을 함께 보내야 한다(SHALL). 추천을 불러오는 동안에는 "분류하는 중"을 보이고, 실패하면 칸을 비우고 분석 중에 정한다고 알린다.

#### Scenario: 올린 문서의 분류 추천 보기
- **WHEN** 엔지니어가 검토 등록에서 docx 하나를 올리면
- **THEN** 몇 초 안에 그 줄에 문서 종류, 묶음, 언어, 판정 대상 여부와 이유가 보인다

#### Scenario: 묶음을 바꿔 시작
- **WHEN** 엔지니어가 묶음 C로 추천된 문서를 묶음 B로 바꾸고 등록하고 분석을 시작하면
- **THEN** 시작 요청에 그 문서의 묶음 B가 함께 가고, 그 줄에 "사람이 바꿈"이 보인다

### Requirement: 사업 현황 화면
화면은 사업 현황(SCR-04)에 실제 사업 목록을 목업 v4.57 레이아웃으로 보여야 한다(SHALL): 요약(진행 중 사업, 3일 내 제출 마감, 마감 지남), "내 사업 · 팀 전체", 찾기(상태, 국가, 제출 마감, 검색어), 사업 줄(순번, 사업명, 고객사 · 국가, 고객 입찰 번호, 제출 마감 D-n, 범위별 상태 칩, 내 역할, 영업). "내 사업"은 머리글에서 고른 사용자 기준이다. 예시 띠는 없다. 처리 중인 검토가 있는 동안 목록을 다시 불러온다. [결정] "등록 전 범위" 칸은 숨긴다.

#### Scenario: 사업 현황 열기
- **WHEN** 엔지니어가 자기 검토가 연결된 사업이 있는 상태로 왼쪽 메뉴의 사업 현황을 열면
- **THEN** 예시 띠 없이 그 사업 줄이 마감 가까운 순으로 범위 상태 칩, 내 역할 "엔지니어"와 함께 보인다

#### Scenario: 반려 칩
- **WHEN** 반려된 검토가 연결된 사업을 사업 현황에서 보면
- **THEN** 그 범위 칩이 빨간 "반려"로 보이고 마우스를 올리면 범위 · 담당이 보인다

#### Scenario: 팀 전체
- **WHEN** 사업 현황에서 "팀 전체"를 누르면
- **THEN** 고른 사용자와 관계없는 사업도 함께 보인다

### Requirement: 사업 상세 화면
화면은 사업 상세(SCR-05, `#/projects/<사업 번호>`)에 사업 정보와 개요(범위 카드)·담당자·일정·문서 탭을 실제 데이터로 보여야 한다(SHALL). 범위 카드를 누르면 상태에 맞는 화면(검토 상세, 협조 요청 현황, 결재)으로 간다. 사업 정보 고치기, 제출 완료 표시·취소, "이 사업에 RFP 등록"(검토 등록에 이 사업을 고른 채 열기) 단추가 있다. 지난 이력 탭은 예시 띠와 함께 예시로 남긴다.

#### Scenario: 범위 카드에서 검토로
- **WHEN** 사업 상세 개요에서 "판정 확인" 범위 카드를 누르면
- **THEN** 그 검토의 검토 상세가 열린다

#### Scenario: 이 사업에 RFP 등록
- **WHEN** 사업 상세에서 "이 사업에 RFP 등록"을 누르면
- **THEN** 검토 등록 화면이 "진행 중인 사업에 추가"와 그 사업이 고른 채로 열린다

#### Scenario: 제출 완료 단추
- **WHEN** 결재 대기 검토가 있는 사업 상세를 열면
- **THEN** "제출 완료로 표시" 단추가 잠겨 있고 모든 검토가 승인되어야 한다는 안내가 보인다

#### Scenario: 지난 이력은 예시
- **WHEN** 사업 상세에서 지난 이력 탭을 열면
- **THEN** 탭 안에 "예시 화면 · 실제 데이터와 연결되지 않음" 띠가 보인다

### Requirement: 검토 등록 사업 연결
화면은 검토 등록의 검토 정보 단계에 "사업 연결"(새 사업 만들기 / 진행 중인 사업에 추가)을 보여야 한다(SHALL). 새 사업은 사업명을 받고, 진행 중인 사업은 제출 완료가 아닌 사업 목록에서 고른다. 사업을 고르면 고객사·국가·마감 칸을 사업 값으로 미리 채우고 사람이 고칠 수 있다. 검토 머리글의 사업명을 누르면 사업 상세로 간다.

#### Scenario: 사업 고르면 미리 채움
- **WHEN** 검토 등록에서 "진행 중인 사업에 추가"로 고객사가 든 사업을 고르면
- **THEN** 고객사·국가·마감 칸이 그 사업 값으로 채워지고 검토명 안내가 "<사업명> · 설비 범위"로 바뀐다

#### Scenario: 머리글에서 사업으로
- **WHEN** 사업에 연결된 검토의 검토 상세 머리글에서 사업명을 누르면
- **THEN** 그 사업의 사업 상세가 열린다

### Requirement: 실행 기록 화면
시스템은 지식 관리 메뉴의 "실행 기록" 화면에 요약(실행 수, 끝난 실행 평균 걸린 시간, AI 요청 합, 추정 비용 합)과 검토마다 한 줄(검토, 상태, 시작, 걸린 시간, 모델, 요청·재시도, 토큰, 추정 비용, 문서·다시 쓴 문서, 요구사항, 판정, 다시 시도)을 보여야 한다(SHALL). 줄을 누르면 단계별 걸린 시간을 펼친다. 추정 비용에는 "팀 가정"을 붙인다(CR-06). 기록 전 실행은 "기록 없음"으로 보인다. [제안]

#### Scenario: 실행 기록 보기
- **WHEN** 엔지니어가 실행 기록 화면을 열고 방금 끝난 검토 줄을 누르면
- **THEN** 그 줄에 검토 번호, 걸린 시간, 요청 수, 다시 쓴 문서 수가 보이고, 단계별 걸린 시간에 문서 읽기와 판정이 보인다

### Requirement: 제품표 상세의 제품 사진
화면은 제품표 상세 패널 위쪽에 그 제품 카탈로그 계열의 대표 사진을 보이고, 사진 아래에 "이 모델만의 사진은 아님"과 사진 출처(공식 페이지 링크)를 적어야 한다(SHALL). 사진이 없는 카탈로그의 제품은 사진 대신 "공식 사진 없음"을 보여야 한다(SHALL). 사진은 판정·보증값 계산에 쓰지 않는다. [결정]

#### Scenario: 제품 상세에 계열 사진
- **WHEN** 엔지니어가 제품표에서 GIS 제품을 누르면
- **THEN** 상세 패널에 "GIS 대표 사진"과 "이 모델만의 사진은 아님", LS ELECTRIC 공식 사이트로 가는 출처 링크가 보인다

#### Scenario: 사진이 없는 카탈로그
- **WHEN** 사진 짝이 없는 카탈로그 번호를 출처로 가진 제품을 고르면
- **THEN** 사진 자리에 "공식 사진 없음"이 보인다

### Requirement: 제품표 상세의 관련 문서
화면은 제품표 상세 패널의 "문서" 탭에 그 제품 카탈로그 계열의 공식 자료실 문서를 카탈로그·매뉴얼·시험 성적서·인증서로 묶어 내려받기 링크로 보여야 한다(SHALL). 제품표 값의 출처와 같은 번호의 카탈로그에는 "제품표 값의 출처"를 붙이고, 공식 자료실에 없는 종류는 "공식 자료실에 없음"으로 보여야 한다(SHALL). 문서는 계열 공통 자료임을 함께 적는다. [결정]

#### Scenario: 제품 상세 문서 탭
- **WHEN** 엔지니어가 제품표에서 GIS-145-40을 고르고 "문서" 탭을 누르면
- **THEN** 카탈로그에 "[GIS] Total Solution"과 "제품표 값의 출처"가, 시험 성적서에 GIS TypeTest 링크가 보이고, 5건이 넘으면 "더 보기"로 나머지를 펼친다

#### Scenario: 공식 자료실에 없는 문서 종류
- **WHEN** 엔지니어가 SWGR-GSH20V-24의 "문서" 탭을 누르면
- **THEN** 카탈로그에 "[GSH-20V]_국문"이 보이고, 시험 성적서에는 "공식 자료실에 없음"이 보인다

### Requirement: 상업 조건 탭
화면은 상업 조건 탭에 비용 조건 요약(조항 종류와 위험 표시, 원문과 값, 부담 표시, 원문 위치, 담당, 협조 요청 상태)과 기술 판단에서 생긴 상업 영향(종류, 내용, 판정·손실 환산 연결, 팀 가정 표시)을 목업 v4.57 표 모양으로 보여야 한다(SHALL). 종류 칩(건수)으로 거르고, 줄마다 "후보"임을 보인다. 금액은 계산하지 않는다. 보내기는 협조 요청 현황에서 한다.

#### Scenario: 상업 조건 탭 열기
- **WHEN** 지체상금 줄이 있는 검토 상세에서 "상업 조건" 탭을 누르면
- **THEN** 예시 띠 없이 "지체상금" 줄이 원문 위치·견적 담당·협조 요청 상태와 함께 보이고 머리 표시에 비용 조건 수가 보인다

#### Scenario: 종류 칩으로 거르기
- **WHEN** 상업 조건 탭에서 "하자 보증" 칩을 누르면
- **THEN** 하자 보증 줄만 남고 그 칩이 눌린 상태로 보인다

#### Scenario: 비용 조건이 없는 검토
- **WHEN** 비용 영향 줄이 없는 검토의 상업 조건 탭을 열면
- **THEN** "찾은 비용 조건이 없습니다" 안내가 보이고 내려받기·보내기 단추는 없다

### Requirement: 판정 탭의 공학 검산 표시
시스템은 판정 탭에서 공학 규칙 검산(FR-12) 결과를 보여야 한다(SHALL). 검산이 위반이거나 확인 필요인 최대 순간 전류·단시간 전류 줄에는 판정 표에 "검산 위반" 또는 "검산 확인 필요" 표시를 붙이고, 판정 탭 머리에 위반·확인 필요 수를 보인다. 오른쪽 패널과 판정 상세 창에는 서버가 저장한 값으로 계산식, 원문 값, 결과(통과·위반·확인 필요와 이유)를 보인다. 화면은 값을 새로 계산하거나 판정을 바꾸지 않는다(CR-01). [결정]

#### Scenario: 검산 위반 줄
- **WHEN** 230 kV 차단기 표(50 Hz, 차단 전류 50 kA, 최대 순간 전류 100 kA)와 주파수가 없는 표가 있는 검토의 판정 탭을 열면
- **THEN** 그 최대 순간 전류 줄에 "검산 위반"이 보이고 머리에 "공학 검산 위반 1건 · 확인 필요 1건"이 보인다

#### Scenario: 검산 계산식 보기
- **WHEN** 그 줄을 눌러 오른쪽 패널을 열면
- **THEN** "공학 검산" 칸에 "50 kA × 2.5 = 125 kA"와 원문 "100 kA", "위반"이 보인다

#### Scenario: 통과한 검산
- **WHEN** 검산을 통과한 최대 순간 전류 줄(115 kV GIS, 40 kA, 100 kA, 50 Hz)을 열면
- **THEN** 표에는 검산 표시가 없고, 패널 "공학 검산" 칸에 "통과"와 계산식이 보인다

### Requirement: 지난 RFP 비교 탭
화면은 지난 RFP 비교 탭에 같은 고객사의 지난 검토를 고르는 "비교 대상"(검토 번호·제목·시작 연월), 지난 검토 요약(검토 번호는 그 검토 상세로, 시작일, 판정 줄 수, 비교 제품, 단계), 건수 칸(달라진 요구·값 바뀜·새로 생김·사라짐, 누르면 그 구분만), 비교 표(구분, 항목과 설비, 지난·이번 값, 판정 변화, 참고), "같은 요구 n줄은 … 숨겼습니다"를 보여야 한다(SHALL). 대상을 바꾸면 거르기가 풀린다. 고객사가 없으면 고객사를 넣으라는 안내를, 대상이 없으면 대상이 없다는 안내를 보인다. 저장하지 않는다. [제안]

#### Scenario: 같은 고객사 지난 검토와 비교
- **WHEN** 같은 고객사로 처리를 마친 지난 검토가 있는 다음 입찰 검토의 지난 RFP 비교 탭을 열고 "새로 생김" 칸을 누르면
- **THEN** 비교 대상에 지난 검토가 골라져 있고 예시 띠는 없으며, 표에 새로 생긴 요구만 남고 그 칸이 눌린 상태로 보인다

#### Scenario: 고객사 없음 안내
- **WHEN** 고객사를 넣지 않은 검토의 지난 RFP 비교 탭을 열면
- **THEN** 표 대신 검토 정보에 고객사를 넣으라는 안내가 보인다

### Requirement: 검토 목록 내가 올린 결재 보기
검토 목록은 담당 범위에 "내가 올린 결재" 보기를 두어, 머리글에서 고른 사용자가 상신한 검토만 결재 대기·반려·승인으로 나눠 개수와 함께 보여야 한다(SHALL). 이 보기의 각 줄에는 결재자와 상신 후 날 수 또는 결정 시각을 보여야 한다(SHALL). 결재자 전용 보기와 새 메뉴는 만들지 않는다. [결정]

#### Scenario: 내가 올린 결재 보기
- **WHEN** 엔지니어가 검토 두 개를 상신하고 그중 하나가 반려된 상태에서 검토 목록의 "내가 올린 결재"를 고르면
- **THEN** 두 검토만 보이고 결재 대기 1 · 반려 1이 보이며, 각 줄에 결재자 이름이 보인다

#### Scenario: 다른 사람이 올린 결재
- **WHEN** 다른 엔지니어가 상신한 검토가 있는 상태에서 "내가 올린 결재"를 고르면
- **THEN** 그 검토는 보이지 않는다

### Requirement: 요약 줄로 결재 대기 거르기
검토 목록 요약 줄의 "결재 대기 n"을 누르면 단계 거름이 결재 대기로 바로 적용되어야 한다(SHALL).

#### Scenario: 요약 줄로 결재 대기 거르기
- **WHEN** 결재 대기 검토가 2개 있는 상태에서 요약 줄의 "결재 대기 2"를 누르면
- **THEN** 표에 결재 대기 검토 2개만 보이고 찾기 상자의 단계가 결재 대기로 바뀐다

### Requirement: 정답지·채점 화면
화면은 정답지·채점(SCR-19)에서 채점 결과(지표, 무엇을 재나, 지난, 이번, 변화, 목표), 정답지(사람이 판정을 확정한 검토와 넣기 체크, 유형 정답지와 "Claude 초안·사람 확인 전" 표시), 개선 기록(채점 기록)을 실제 데이터로 보이고, "지금 채점하기"로 넣은 검토·고른 정답지·메모로 채점해야 한다(SHALL). 예시 띠를 붙이지 않는다. [제안]

#### Scenario: 지금 채점하기
- **WHEN** 사람이 판정을 확정한 검토가 있는 상태에서 정답지·채점 화면의 "지금 채점하기"를 누르면
- **THEN** 채점 결과 탭에 K5와 처리 시간 값이 보이고 개선 기록에 새 줄이 생긴다

#### Scenario: Claude 초안 표시
- **WHEN** Claude 초안 유형 정답지가 들어 있는 상태에서 정답지 탭을 열면
- **THEN** 그 정답지에 "Claude 초안 · 사람 확인 전"과 사람 확인 줄 수가 보인다

### Requirement: 판정 탭 지난 확정 표시
화면은 판정 탭에서 지난 사람 판정이 있는 줄의 판정 칸에 "지난 확정 <판정>" 꼬리표를 보이고, 지금 판정과 다르면 "지난 확정과 다름"으로 눈에 띄게 해야 하며(SHALL), 판정 상세 패널에 지난 검토 번호(링크), 판정, 사람, 날짜, 사유를 보여야 한다(SHALL). 다른 줄이 있으면 칩 "지난 확정과 다름 n"으로 그 줄만 거를 수 있어야 한다(SHALL). [제안]

#### Scenario: 지난 확정과 다른 줄 거르기
- **WHEN** 지난 검토에서 고친 판정과 같은 줄이 있는 새 검토의 판정 탭에서 "지난 확정과 다름" 칩을 누르면
- **THEN** 그 줄만 보이고 줄에 "지난 확정과 다름" 꼬리표가, 상세 패널에 지난 검토 번호와 사유가 보인다

### Requirement: 사전 추가 제안 화면
화면은 위험 조건 탭 "사람이 찾은 특이 요구"에서 놓친 표현과 메모를 넣어 제안하고 이 검토의 제안(표현, 찾은 곳, 상태)을 보여야 하며, 판정 규칙 화면 "사람이 제안한 표현"에서 제안을 확인 대기부터 보이고 엔지니어·승인자에게 [반영]·[반려]를 보여야 한다(SHALL). [반영]은 표현을 채운 규칙 추가 창을 연다. 예시 띠를 붙이지 않는다. [제안]

#### Scenario: 제안하고 반영하기
- **WHEN** 엔지니어가 위험 조건 탭에서 문서에 있는 표현을 제안하고, 판정 규칙 화면에서 그 제안을 반영하면
- **THEN** 위험 조건 탭에 "확인 대기"로 보였던 제안이 판정 규칙 화면에서 "반영"으로 바뀌고 위험 표현 탭에 그 표현이 보인다

### Requirement: 검토 도우미 창
화면은 분석이 끝난 검토 상세 머리글에 "검토 도우미" 단추를 두고, 누르면 오른쪽 창에 질문 칸, 예시 질문, 답 문장(문장마다 근거 번호), 근거 줄(원문, 원문 위치, 판정이면 판정 값), 찾은 경로, "AI가 쓴 문장 · 근거와 대조함"(AI 없으면 "AI 없이 글자로 찾음")을 보여야 한다(SHALL). 창에는 고치기 단추가 없다. [제안]

#### Scenario: 도우미에 묻기
- **WHEN** 엔지니어가 검토 도우미 창에서 "ambient temperature"를 물으면
- **THEN** 창에 그 글자가 들어간 근거 줄과 원문 위치가 보인다

### Requirement: 버린 AI 설명 표시
화면은 실행 기록 화면 검토 줄에 버린 AI 설명 수를 보이고(0이면 보이지 않음), 위험 조건 탭에서 설명을 버린 줄의 설명 칸에 "AI 설명 버림"과 이유(없는 근거 ID, 근거에 없는 인용, 근거에 없는 숫자, 형식 오류)를 보여야 한다(SHALL). [제안 11-01]

#### Scenario: 버린 설명 보기
- **WHEN** 설명 하나가 근거에 없는 숫자로 버려진 검토의 위험 조건 탭과 실행 기록 화면을 열면
- **THEN** 그 위험 조건 줄에 "AI 설명 버림 · 근거에 없는 숫자"가, 실행 기록 줄에 "AI 설명 버림 1"이 보인다

### Requirement: 한꺼번에 확정에서 뺀 줄 알림
화면은 한꺼번에 확정 뒤 확정한 줄 수와 함께 뺀 줄 수와 이유별 수(검산, 숫자 불일치, 값 없음)를 알리고 한 줄씩 확인하라고 안내해야 한다(SHALL). [제안 11-01]

#### Scenario: 뺀 줄 알림
- **WHEN** 엔지니어가 고른 줄 중 1줄이 검산 위반으로 빠진 채 한꺼번에 확정되면
- **THEN** "1줄은 뺐습니다(검산 1)"와 한 줄씩 확인하라는 안내가 보인다

### Requirement: AI 검증 표시
화면은 위험 조건 탭에서 검증이 확인 필요인 설명 옆에 "AI 검증: 확인 필요"를, 실행 기록 화면 검토 줄에 검증 확인 필요 수를(0이면 보이지 않음) 보여야 한다(SHALL). [제안 11-01]

#### Scenario: 검증 확인 필요 보기
- **WHEN** 설명 하나가 검증에서 확인 필요인 검토의 위험 조건 탭과 실행 기록 화면을 열면
- **THEN** 그 위험 조건 줄에 "AI 검증: 확인 필요"가, 실행 기록 줄에 "검증 확인 필요 1"이 보인다

### Requirement: 요구사항 정답지 고르기 화면
화면은 정답지·채점 화면 정답지 탭에서 유형 정답지와 따로 요구사항 정답지 목록(이름, 대상 문서, 줄 수, 만든 이)을 보이고 하나를 골라 채점하게 해야 한다(SHALL). 코드가 만든 정답지에는 "코드 자동 · 사람 확인 전"을 붙이고, 판정 줄이 없는 검토는 "판정 0줄"로 보이되 처음에는 넣지 않는다. 요구사항 정답지로 채점하면 채점 결과에 K1·K2·K3·K10이 보인다. [제안 11-01]

#### Scenario: 요구사항 정답지로 채점
- **WHEN** 코드 자동 요구사항 정답지가 있는 상태에서 정답지 탭을 열어 그 정답지를 고르고 "지금 채점하기"를 누르면
- **THEN** 정답지에 "코드 자동 · 사람 확인 전"과 대상 문서가 보이고, 채점 결과 탭에 K1 값이 보인다

### Requirement: 뜻 찾기 표시
화면은 위험 조건 탭에 "사전 추가 후보"(문장, 가까운 문장·표현, 점수, 원문 위치, [사전 추가 제안])와 뜻 찾기 상태(안 함·건너뜀)를 보이고, 판정 탭 지난 확정 꼬리표에 뜻으로 찾은 것이면 "뜻 비슷 0.93"처럼 점수를 붙이며, 판정 규칙 화면 "항목 이름" 탭에 연결 후보와 엔지니어·승인자용 [같은 뜻 표현으로 추가]·[숨기기]를 보여야 한다(SHALL). [제안 11-01]

#### Scenario: 사전 추가 후보 보기
- **WHEN** 사전 추가 후보가 있는 검토의 위험 조건 탭을 열면
- **THEN** 후보 문장과 점수, 가까운 문장이 보이고 [사전 추가 제안]을 누르면 아래 제안 칸에 그 문장(100자까지)과 메모가 채워진다

#### Scenario: 항목 연결 후보 받아들이기
- **WHEN** 엔지니어가 판정 규칙 화면 항목 이름 탭의 연결 후보에서 [같은 뜻 표현으로 추가]를 누르면
- **THEN** 후보가 목록에서 빠지고 알림이 보인다

# review-workspace Specification

## Purpose
엔지니어가 위험 조건과 내세울 강점을 원문 위치와 함께 먼저 보고 판단만 하도록, 검토 결과를 한국어 요약 + 원문으로 보여 주는 화면이다 (NFR-08).

## Requirements

### Requirement: 문서 올리기와 실행 상태
화면은 docx를 올려 검토를 시작하고, 실행의 현재 단계와 실패 메시지("처리 실패 — 다시 시도")를 보여 줘야 한다(SHALL).

#### Scenario: 처리 중
- **WHEN** 엔지니어가 파일 1을 올리면
- **THEN** 실행이 시작되고 현재 단계가 보인다

### Requirement: 근거와 함께 보이는 결과
화면은 요구사항(유형 칸 포함), 위험 조건, 적합성 판정, 보증값 후보, 일탈·질의 목록, 제안 포인트를 보여 주고, 각 줄에서 원문 위치와 원문을 볼 수 있어야 한다(SHALL). 팀 가정 값이 들어간 줄에는 "팀 가정"이 보여야 한다(SHALL).

#### Scenario: 적합성 표의 비교 제품
- **WHEN** 엔지니어가 적합성 표를 열면
- **THEN** 각 판정의 비교 제품, 제품값, 여유와 방향이 보이고 비교 제품을 바꿔 볼 수 있다

#### Scenario: 손실 환산 결과
- **WHEN** 엔지니어가 손실 환산 결과를 열면
- **THEN** 계산식, 합계, "팀 가정" 표시가 보인다

### Requirement: 판단 동작
화면은 각 후보에 확정·수정·반려(제안 포인트는 채택·버림·수정)를 사유와 함께 남기게 하고, 결재 상신 창에서 지금 걸리는 승인 기준을 미리 보여 주며 결재자와 상신 의견을 받아야 한다(SHALL). 승인자에게는 상신 의견, 걸린 승인 기준과 누락 점검 결과를 보여 주고, 엔지니어에게는 결정 전 상신 취소 버튼을 보여 줘야 한다(SHALL).

#### Scenario: 승인 화면
- **WHEN** 승인자가 승인 대기 실행을 열면
- **THEN** 상신 의견, 걸린 승인 기준, 일탈 후보 수, 목록에 들어간 수, 빠진 일탈이 보인다

#### Scenario: 결재 상신 창
- **WHEN** 엔지니어가 일탈 후보가 있는 검토에서 결재 상신 창을 열면
- **THEN** 지금 걸리는 기준 AR-01이 보이고, 결재자와 상신 의견을 넣기 전에는 상신 버튼이 눌리지 않는다

### Requirement: 내 할 일 화면
화면은 고른 사용자 역할의 "내 할 일"을 보여 줘야 한다(SHALL). 견적·품질·영업 담당은 전달받은 할 일(유형 또는 제안 포인트 종류, 반복 표시, 원문 위치, 상태), 기술 검토 엔지니어는 담당자 확인 중인 검토, 승인자는 자기에게 상신된 승인 대기 검토를 걸린 승인 기준과 함께 본다(SHALL).

#### Scenario: 견적 담당 내 할 일
- **WHEN** 견적 담당 사용자를 고르고 "내 할 일"을 열면
- **THEN** 손실 환산 조항 할 일이 원문 위치와 상태 버튼과 함께 보인다

#### Scenario: 엔지니어·승인자의 내 할 일
- **WHEN** 엔지니어가 "내 할 일"을 열면 담당자 확인 중인 검토가, 승인자가 열면 자기에게 상신된 승인 대기 검토가 보이고
- **THEN** 카드마다 걸린 승인 기준이 보이고 누르면 그 검토가 열린다

#### Scenario: 다른 결재자에게 간 검토
- **WHEN** 승인자 두 명 중 한 명에게만 상신된 검토가 있을 때 다른 승인자가 "내 할 일"을 열면
- **THEN** 그 검토는 보이지 않는다

### Requirement: 앱 틀과 화면 주소
화면은 목업과 같은 왼쪽 메뉴(홈, RFP 관리, 지식 관리, 팀 공유, 설정)와 머리글(메뉴 접기, 현재 위치, 검색, 알림, 사용자)을 모든 화면에 보여 줘야 한다(SHALL). 화면마다 주소가 있어 주소로 바로 열거나 새로 고쳐도 같은 화면과 메뉴 강조가 보여야 한다(SHALL). 메뉴 접기 상태는 브라우저에 기억해야 한다(SHALL).

#### Scenario: 메뉴로 화면 이동
- **WHEN** 엔지니어가 RFP 검토 화면에서 지식 관리 > 제품 관리를 누르면
- **THEN** 주소가 제품 관리 화면 주소로 바뀌고 제품 관리 메뉴가 강조되며 현재 위치에 홈과 제품 관리가 보인다

#### Scenario: 메뉴 접기
- **WHEN** 사용자가 메뉴 접기를 누르고 화면을 새로 고치면
- **THEN** 메뉴는 아이콘만 남은 접힌 상태로 보인다

### Requirement: 머리글 사용자 고르기
로그인이 없으므로 화면은 머리글 사용자 칩에서 사용자를 바꾸게 하고, 고른 사용자의 이름과 역할을 머리글에 보여 주며, 모든 화면의 권한을 그 역할로 정해야 한다(SHALL). 고른 사용자는 브라우저에 기억해야 한다(SHALL).

#### Scenario: 사용자 바꾸기
- **WHEN** 엔지니어로 보던 사용자가 사용자 칩에서 기본 승인자를 고르면
- **THEN** 머리글에 기본 승인자와 승인자 역할이 보이고 새로 고쳐도 유지된다

### Requirement: 예시로 보이는 알림
알림 API가 없는 동안 화면은 머리글 알림을 예시 데이터로 보여 주고 "예시" 표시를 붙여야 한다(SHALL). 예시 알림은 저장하지 않는다.

#### Scenario: 알림은 예시로 보인다
- **WHEN** 사용자가 머리글 알림 단추를 누르면
- **THEN** "예시" 표시가 붙은 알림 목록이 보이고 모두 읽음으로 하면 읽지 않은 수가 0이 된다

### Requirement: 검토 정보 입력과 표시
화면은 검토를 시작할 때 검토 정보(사업명, 검토명, 고객사, 국가, 제출 마감일, 담당 엔지니어)를 넣을 칸을 보여 주고, 검토 목록과 검토 머리글에 검토 번호·검토 정보·마감까지 남은 날(D-day)을 보여 줘야 한다(SHALL). 검토명이 비어 있으면 첫 파일 이름을 대신 보여 준다. 머리글에서 검토 정보를 고칠 수 있어야 한다(SHALL).

#### Scenario: 목록에서 마감 보기
- **WHEN** 마감일이 3일 뒤인 검토가 있는 상태에서 검토 목록을 열면
- **THEN** 그 줄에 검토 번호, 사업명, 검토명, 고객사, 담당 엔지니어, "D-3"과 요구사항·위험·일탈·제안 개수가 보인다

#### Scenario: 검토명이 빈 검토
- **WHEN** 검토 정보 없이 시작한 검토를 목록에서 보면
- **THEN** 검토명 자리에 첫 파일 이름이 보이고 마감 자리는 비어 있다

#### Scenario: 머리글에서 고치기
- **WHEN** 엔지니어가 검토 머리글에서 고객사를 고치고 저장하면
- **THEN** 머리글과 목록에 새 고객사가 보이고 이력 탭에 그 변경이 보인다

### Requirement: 검토 상세 요약 칸과 탭
화면은 처리를 마친 검토 상세의 머리글 아래에 요약 칸 5개(일탈 후보, 질의 후보, 확인 필요 비율과 기준, 보증값 작성, 손실 환산 참고값)와 탭 9개(판정, 문서 읽기 점검, 위험 조건, 손실 환산(참고), 입찰 영향, 상업 조건, 지난 RFP 비교, 제출본, 이력)를 목업 순서대로 보여야 한다(SHALL). API가 없는 탭은 예시 띠를 붙인다(SHALL).

#### Scenario: 요약 칸
- **WHEN** 일탈 후보가 있는 검토 상세를 열면
- **THEN** 요약 칸에 일탈 후보 수, 질의 후보 수, 확인 필요 비율과 "기준 20 %", 보증값 작성 수, 손실 환산 참고값이 보인다

#### Scenario: 탭으로 내용 바꾸기
- **WHEN** 검토 상세에서 "이력" 탭을 누르면
- **THEN** 이력 표가 보이고 탭 줄에서 이력 탭이 선택된 것으로 보인다

#### Scenario: 예시 탭
- **WHEN** "상업 조건" 탭을 누르면
- **THEN** 예시 띠가 보이고, 단추를 눌러도 저장하지 않아 화면을 다시 열면 처음 내용으로 돌아온다

### Requirement: 판정 표 거르기
화면은 판정 탭에 판정 칩(전체와 판정 값마다, 건수), "확정 안 한 줄만", 검색어, 유형 거르기를 두고 판정 순서로 정렬한 판정 표(판정, 항목 이름·영문, 요구값, 제품값·보증값, 원문 위치)를 페이지로 나눠 보여야 한다(SHALL). 표 아래에 보이는 줄 수와 전체 판정 수를 보인다(SHALL).

#### Scenario: 판정 칩으로 거르기
- **WHEN** 판정 탭에서 "일탈 후보" 칩을 누르면
- **THEN** 표에는 일탈 후보 줄만 보이고 칩의 건수와 표 아래 줄 수가 같다

#### Scenario: 거른 결과가 없음
- **WHEN** 맞는 줄이 없는 검색어를 넣으면
- **THEN** "조건에 맞는 줄이 없습니다"와 필터 지우기가 보인다

### Requirement: 판정 상세 패널
화면은 판정 줄을 누르면 오른쪽 패널에 원문 위치와 원문 문장, 판정 근거, 판정 출처(시스템 제안과 담당자 확정), 그 판정에서 나온 일탈·질의 목록 문장, 판정 바꾸기를 보여야 한다(SHALL). 판정을 바꾸려면 사유가 있어야 하고(MUST), 담당자 확인 단계에서만 바꾸거나 확정할 수 있다(SHALL).

#### Scenario: 줄을 눌러 원문 보기
- **WHEN** 판정 표에서 일탈 후보 줄을 누르면
- **THEN** 패널에 원문 위치, 원문 문장, 판정 근거, "시스템 제안 일탈 후보"와 "아직 확정 안 함"이 보인다

#### Scenario: 사유 없이 판정 바꾸기
- **WHEN** 패널에서 새 판정을 고르고 사유를 비우면
- **THEN** 적용 단추가 눌리지 않고, 사유를 넣고 적용하면 표의 판정과 담당자 확정이 바뀐다

### Requirement: 위험 조건 탭
시스템은 위험 조건 탭 머리에 닫지 않은 위험 조건 수를 종류별로 보이고, 위험 조건마다 상태, 종류와 표현 또는 항목 이름·값, 설명, 원문 위치를 한 줄로 보여야 한다(SHALL). 문제 없음으로 닫은 줄은 흐리게 맨 아래에 두고 닫은 사유와 누가·언제 닫았는지 보인다. 엔지니어는 담당자 확인 단계에서 후보를 위험으로 확정하거나, 사유를 적어 문제 없음으로 닫을 수 있다(SHALL).

#### Scenario: 위험 조건 건수
- **WHEN** 포괄 조항·값 불일치·범위 모호 후보가 하나씩 있는 실행의 위험 조건 탭을 열면
- **THEN** 머리에 "포괄 조항 1 · 값 불일치 1 · 범위 모호 1"이 보이고, 줄 3개에 "후보" 배지와 원문 위치가 보인다

#### Scenario: 문제 없음으로 닫기
- **WHEN** 엔지니어가 값 불일치 후보에서 문제 없음을 누르고 사유를 적어 닫으면
- **THEN** 그 줄은 "문제 없음" 배지로 흐리게 맨 아래에 가고, 사유와 닫은 사람이 보이며, 머리의 값 불일치 수가 0이 된다

#### Scenario: 사유 없이 닫기
- **WHEN** 문제 없음 사유 칸이 비어 있으면
- **THEN** 닫기 단추가 눌리지 않는다

#### Scenario: 위험으로 확정
- **WHEN** 엔지니어가 포괄 조항 후보를 위험으로 확정하면
- **THEN** 그 줄의 배지가 "확정"이 되고 확정한 사람이 보인다

### Requirement: 사람이 찾은 특이 요구 예시
시스템은 위험 조건 탭에서 사람이 찾은 특이 요구를 위험 표현 사전에 제안하는 영역을 예시 띠와 함께 보여야 하며, 이 영역의 단추는 저장하지 않는다(SHALL). 제안을 받아 저장하는 API는 아직 없다.

#### Scenario: 특이 요구 제안은 예시
- **WHEN** 위험 조건 탭에서 놓친 표현을 넣고 제안 추가를 누르면
- **THEN** 영역에 예시 띠가 보이고, 넣은 표현이 "제안함" 줄로 보이지만 서버에는 요청을 보내지 않는다

### Requirement: 손실 환산 탭
시스템은 손실 환산 탭에 고객 손실 환산 조항이 있을 때만 계산한 참고값이라는 안내, 단가 행 위치, 무부하·부하·보조마다 단가·손실값·가산액, 가산액 합계를 보여야 한다(SHALL). 엔지니어는 담당자 확인 단계에서 손실값을 넣어 다시 계산할 수 있고, 직접 넣은 값이 들어간 결과에는 "팀 가정"을 보인다(SHALL). 조항이 없으면 계산하지 않았다고 알린다.

#### Scenario: 손실 환산 표
- **WHEN** 손실 환산 단가 행이 있고 비교 제품이 없는 실행의 손실 환산 탭을 열면
- **THEN** 무부하·부하·보조 줄에 단가가 보이고, 손실값 칸은 비어 있으며, 가산액 합계는 "—"이다

#### Scenario: 손실값 넣어 다시 계산
- **WHEN** 엔지니어가 세 손실값을 60·300·8 kW로 넣으면
- **THEN** 줄마다 가산액과 합계 $1,240,400이 보이고 "팀 가정" 표시가 붙는다

#### Scenario: 조항 없는 RFP
- **WHEN** 손실 환산 조항이 없는 실행의 손실 환산 탭을 열면
- **THEN** "이 RFP에는 손실 환산 조항이 없어 계산하지 않았습니다."가 보인다

### Requirement: 입찰 영향 탭
시스템은 입찰 영향 탭에 유리한 점으로 제안 포인트(근거, 상태, 문장, 종류와 원문 위치, 팀 가정·숫자 불일치 표시)를, 불리한 점으로 일탈 후보와 질의 후보 판정(항목 이름 + "미달" 또는 "값 불명확", 대응 문장)을 보여야 한다(SHALL). 엔지니어는 담당자 확인 단계에서 제안 포인트를 채택하거나 사유를 적어 버릴 수 있다(SHALL). 불리한 점이 없으면 "불리한 점이 없습니다."를 보인다.

#### Scenario: 제안 포인트 채택
- **WHEN** 엔지니어가 후보 상태의 제안 포인트에서 채택을 누르면
- **THEN** 그 포인트 채택 요청이 가고 상태가 "채택"으로 바뀐다

#### Scenario: 사유 없이 버리기
- **WHEN** 제안 포인트의 버림을 누르고 사유 칸이 비어 있으면
- **THEN** 버리기 단추가 눌리지 않는다

#### Scenario: 불리한 점 목록
- **WHEN** 일탈 후보 1건과 질의 후보가 있는 실행의 입찰 영향 탭을 열면
- **THEN** 불리한 점에 일탈 후보는 "미달", 질의 후보는 "값 불명확" 줄로 대응 문장과 함께 보인다

### Requirement: 머리글 비교 제품 고르기
시스템은 검토 상세 머리글에 비교 제품이 있는 설비 묶음마다 묶음 이름과 후보 제품 단추를 보이고 지금 비교 제품을 표시해야 한다(SHALL). 엔지니어가 담당자 확인 단계에서 다른 제품을 누르면 그 묶음을 다시 판정하고 탭 본문을 새로 불러온다(SHALL).

#### Scenario: 비교 제품 보기
- **WHEN** 판정이 끝난 검토 상세를 열면
- **THEN** 머리글에 "TS-115-GIS 비교 제품"과 지금 제품이 눌린 단추로 보인다

#### Scenario: 비교 제품 바꾸기
- **WHEN** 후보가 둘인 설비 묶음에서 엔지니어가 다른 제품을 누르면
- **THEN** 그 제품으로 바꾸는 요청이 가고, 바뀐 제품이 눌린 단추로 보인다

### Requirement: 이력 탭
시스템은 이력 탭에 수정 이력을 새것부터 시각, 사람, 무엇을 어떻게 바꿨는지 한 줄 문장, 사유(결재·상신은 의견)로 보이고, 맨 아래에 시스템이 판정을 만든 줄을 보여야 한다(SHALL). 문장은 기록된 값만 쓴다.

#### Scenario: 판정 바꾼 이력
- **WHEN** 엔지니어가 판정을 일탈 후보로 바꾼 뒤 이력 탭을 열면
- **THEN** 맨 위 줄에 엔지니어 이름, "판정 "<항목 이름>" <이전 판정> → 일탈 후보", "사유: <사유>"가 보이고 맨 아래 줄은 "시스템 · 판정 n줄 생성"이다

#### Scenario: 위험 조건 닫은 이력
- **WHEN** 위험 조건을 문제 없음으로 닫은 뒤 이력 탭을 열면
- **THEN** "위험 조건 "<표현>" 문제 없음으로 닫음"과 닫은 사유가 보인다

### Requirement: 목록 초안 내려받기와 문장 고치기
시스템은 판정 탭의 "일탈 목록 초안"·"질의서 초안" 단추를 누르면 진행 화면을 보인 뒤 Word 파일을 내려받고 "<파일 이름>를 만들었습니다." 알림을 보여야 한다(SHALL). 일탈·질의 문장은 판정 패널·판정 상세 창(위험 조건에서 나온 문장은 위험 조건 줄을 펼친 곳)에서 보이고, 엔지니어는 담당자 확인 단계에서 문장을 확정하거나, 사유를 적어 고치거나 목록에서 뺄 수 있다(SHALL).

#### Scenario: 일탈 목록 초안 내려받기
- **WHEN** 엔지니어가 판정 탭에서 "일탈 목록 초안"을 누르면
- **THEN** 진행 화면이 보였다가 "일탈 목록 초안_<검토 번호>.docx" 파일이 내려받아지고 만들었다는 알림이 보인다

#### Scenario: 사유 적어 문장 고치기
- **WHEN** 엔지니어가 판정 패널의 질의 문장을 고치면
- **THEN** 사유 칸이 나오고 사유가 비면 문장 저장 단추가 눌리지 않으며, 사유를 적어 저장하면 고친 문장이 "확정" 상태로 남는다

### Requirement: 문서 읽기 점검 탭
시스템은 문서 읽기 점검 탭에 종류별 건수(표·그림·단위·위치), 확인 안 한 건수 표시, 안내 문장과 점검 표(종류와 무엇, 위치·파일·문제·할 일, 확인 단추)를 보여야 한다(SHALL). 엔지니어가 "직접 확인함"을 누르면 "확인함"과 사람·시각, "되돌리기"가 보이고 줄이 흐려진다. 탭 이름 옆에는 확인 안 한 건수를 보인다.

#### Scenario: 점검 줄 확인
- **WHEN** 엔지니어가 문서 읽기 점검 탭에서 한 줄의 "직접 확인함"을 누르면
- **THEN** 그 줄에 "확인함"과 엔지니어 이름이 보이고, 머리 표시와 탭 이름 옆 건수가 하나 줄며, 이력 탭에 "문서 읽기 점검 확인" 줄이 생긴다

#### Scenario: 점검 확인 되돌리기
- **WHEN** 확인한 줄의 "되돌리기"를 누르면
- **THEN** 다시 "직접 확인함" 단추가 보이고 확인 안 한 건수가 늘어난다

#### Scenario: 고칠 수 없을 때 확인 단추
- **WHEN** 엔지니어가 아닌 사용자가 문서 읽기 점검 탭을 열면
- **THEN** "직접 확인함" 단추가 눌리지 않고 이유가 안내된다

### Requirement: 상신 전 확인의 문서 읽기 점검
시스템은 결재 상신 창의 상신 전 확인 목록에 문서 읽기 점검 줄을 넣어야 한다(SHALL). 확인 안 한 점검이 있으면 "문서 읽기 점검 미확인 n건"(주의), 없으면 "문서 읽기 점검 모두 확인"을 보인다. 미확인이 남아도 상신할 수 있다.

#### Scenario: 상신 창의 점검 미확인
- **WHEN** 확인 안 한 점검 줄이 있는 실행에서 결재 상신 창을 열면
- **THEN** 상신 전 확인에 "문서 읽기 점검 미확인 n건"이 주의 표시로 보인다

### Requirement: 상업 조건 예시 탭
시스템은 상업 조건 탭에 목업의 예시 데이터로 RFP 상업 조항 표와 기술 판단에서 생긴 상업 영향 표(고르기, 담당 고르기, 전달 상태, 원문 위치)를 예시 띠와 함께 보여야 한다(SHALL). 고른 항목을 "골라서 전달"하면 화면에서만 전달 상태와 알림을 보이고 저장하지 않는다. 사람 이름 대신 담당 역할을 쓴다. [결정] 상업 조항 추출 API는 팀 결정(차별화 아이디어 C1) 뒤에 만든다.

#### Scenario: 상업 조건 골라서 전달 예시
- **WHEN** 상업 조건 탭에서 미전달 항목 두 개를 고르고 "골라서 전달"을 누르면
- **THEN** 두 줄이 "전달"로 바뀌고 고르기 칸이 잠기며 "상업 조건을 전달했습니다" 알림이 보이고, 머리 표시의 미전달 수가 2 준다

### Requirement: 지난 RFP 비교 예시 탭
시스템은 지난 RFP 비교 탭에 목업의 예시 데이터로 비교 대상 고르기, 지난 입찰 요약, 달라진 요구 건수 칸(달라진 요구·값 바뀜·새로 생김·사라짐), 비교 표(구분, 항목, 지난·이번 요구, 판정 변화, 참고)를 예시 띠와 함께 보여야 한다(SHALL). 건수 칸을 누르면 그 구분만 거른다. 저장하지 않는다. [결정] 같은 고객의 지난 검토를 짝짓는 API는 만들지 않았다.

#### Scenario: 지난 RFP 비교 거르기 예시
- **WHEN** 지난 RFP 비교 탭에서 "새로 생김" 칸을 누르면
- **THEN** 표에 새로 생긴 요구만 남고 그 칸이 눌린 상태로 보이며, 비교 대상을 바꾸면 거르기가 풀리고 그 대상의 건수가 보인다

### Requirement: 제출본 탭
시스템은 제출본 탭에 승인된 실행의 제출본을 버전(v1), 확정 시각(승인 시각), 결재자, 판정 줄 수, 일탈·질의 후보 수, 첨부, 상태("현재 제출본")로 보여야 한다(SHALL). 승인 전이면 제출본이 없다는 안내를 보인다. 승인된 실행은 판정을 고칠 수 없으므로 승인 시점의 판정이 제출본이다. 머리 단추는 승인된 실행에서 "제출본 v1 확정"으로 보인다.

#### Scenario: 승인된 실행의 제출본
- **WHEN** 승인자가 승인한 실행의 제출본 탭을 열면
- **THEN** v1 줄에 결재자 이름, 판정 줄 수, 일탈·질의 후보 수와 "현재 제출본"이 보이고, 머리 단추는 "제출본 v1 확정"이다

#### Scenario: 승인 전 제출본 없음
- **WHEN** 담당자 확인 단계인 실행의 제출본 탭을 열면
- **THEN** "아직 확정된 제출본이 없습니다"로 시작하는 안내가 보인다

### Requirement: 처리 상태 화면
시스템은 처리 중인 검토 상세에 로고, 진행 막대와 백분율, 지금 단계 문장(찾은 문서·요구사항 수 포함)을 보여야 한다(SHALL). 백분율은 처리 단계 순서로만 센다. 처리가 끝나면 다시 묻지 않아도 검토 상세(탭과 요약 칸)로 바뀐다.

#### Scenario: 처리 중인 검토
- **WHEN** 위험 조건 찾기 단계를 처리하는 중인 검토 상세를 열면
- **THEN** 진행 막대의 값이 0보다 크고 100보다 작으며 "위험 조건 찾는 중"이 보이고, 처리가 끝나면 판정 탭이 보인다

### Requirement: 분석 실패 화면
시스템은 처리에 실패한 검토 상세에 멈춘 단계와 오류 문장, 다섯 묶음 진행 상황(끝남·멈춤·대기), 지금 볼 수 있는 결과 수, 문서 목록과 읽은 상태, 처리 기록, 복사할 수 있는 문의용 정보를 보여야 한다(SHALL). 다른 실패한 검토가 있으면 그 검토로 가는 연결을 보인다. 계속하는 방법 고르기는 다시 시도 API가 없어 예시 영역으로 보이고 눌러도 처리하지 않는다(CR-12 재시도는 처리 중 자동으로 정해진 횟수만 한다).

#### Scenario: 분석 실패 상세
- **WHEN** 위험 조건 찾기 단계에서 실패한 검토 상세를 열면
- **THEN** "위험 조건 찾기 단계에서 멈췄습니다"와 오류 문장이 보이고, 진행 상황은 문서 읽기 끝남, 위험 조건 찾기 멈춤, 나머지 대기이며, 문서 목록에 올린 파일 이름이 보인다

#### Scenario: 계속하는 방법 예시
- **WHEN** 실패 화면에서 "남은 부분은 직접 확인"을 고르고 실행 단추를 누르면
- **THEN** 예시 띠가 보이는 영역이고 "예시 화면이라 처리하지 않았습니다" 알림만 보이며 검토 단계는 그대로다

### Requirement: 협조 요청 현황 화면
시스템은 협조 요청 화면에 수신 부서 탭(견적·품질·영업 담당, 미분류), 미확인·24시간 넘게 미확인·확인 수, 요청 표(상태, 요구사항과 검토 번호·원문 위치, 수신자, 요청 일시)를 보여야 한다(SHALL). 요청 항목은 유형별로 보낸 할 일(FR-11)이다. 할 일이면 "미확인", 보낸 지 24시간이 넘으면 "24시간 넘게 미확인", 담당자가 하는 중·끝으로 바꾸면 "확인"이다. 줄을 누르면 요청 내용, 원문, 회신, 근거, 진행을 보이는 창이 열리고, 받는 역할 사용자는 그 창에서 "확인함"·"처리 끝"을 표시한다. [결정] 재요청·회신 글·내보내기 API는 없어 잠그고, 요청하기는 예시 창이다.

#### Scenario: 수신 부서별 요청 현황
- **WHEN** 엔지니어가 협조 요청 화면에서 품질 담당 탭을 고르면
- **THEN** 형식시험 성적서 요청 줄이 "미확인"으로 검토 번호, 파일 이름이 든 원문 위치와 함께 보이고, 요약 줄에 미확인 수가 보인다

#### Scenario: 24시간 넘게 미확인
- **WHEN** 보낸 지 24시간이 넘도록 할 일 상태인 요청이 있으면
- **THEN** 그 줄의 상태가 "24시간 넘게 미확인"이고 상세 창 진행에 "재요청 필요"가 보인다

#### Scenario: 받는 담당자의 확인
- **WHEN** 품질 담당 사용자가 요청 상세 창에서 "확인함"을 누르면
- **THEN** 그 줄은 "확인"으로 흐려지고, 다시 열면 진행에 "확인" 단계와 "처리 끝" 단추가 보인다

#### Scenario: 요청하기 예시
- **WHEN** 엔지니어가 "요청하기" 창에 요구사항과 요청 내용을 적고 "요청 보내기"를 누르면
- **THEN** 예시 띠가 보이는 창이고 "예시 화면이라 보내지 않았습니다" 알림만 보이며 요청 항목 수는 그대로다

### Requirement: 홈 화면
시스템은 홈에 내 업무 네 칸(내가 처리할 건, 결재 대기, 3일 내 마감, 마감 경과)과 내 검토 카드를 단계 열(분석 중, 판정 확인, 협조 대기, 결재 대기, 제출 준비) 또는 사업별로 보여야 한다(SHALL). 엔지니어는 자기가 담당인 검토, 다른 역할은 모든 검토를 본다. 담당자 확인 단계에서 미확인 협조 요청이 남은 검토는 "협조 대기" 열이다. 내 업무 칸을 누르면 그 조건이 아닌 카드를 흐리게 한다. 처리에 실패한 검토가 있으면 위에 알림을 보인다. 팀 업무는 사용자마다 지금 하는 일을 보이고, 공지·시스템 공지·자료실·행사는 예시 영역이다. [결정] 판정 기준 변경 알림과 재시도는 API가 없어 만들지 않는다.

#### Scenario: 내 업무와 단계별 카드
- **WHEN** 엔지니어가 오늘 마감이고 품질 담당 협조 요청이 남은 자기 검토가 있는 상태로 홈을 열면
- **THEN** 그 검토 카드가 "협조 대기" 열에 검토 번호, 검토명, D-Day, 협조 미확인 수와 함께 보이고, "3일 내 마감" 칸 수가 0이 아니다

#### Scenario: 내 업무 칸으로 강조
- **WHEN** 홈에서 "결재 대기" 칸을 누르면
- **THEN** "결재 대기" 필터 칩이 보이고 결재 대기가 아닌 카드는 흐려지며, 칩을 누르면 다시 보통으로 보인다

#### Scenario: 사업별 보기
- **WHEN** 홈에서 "사업별"을 고르면
- **THEN** 카드가 사업 이름 아래로 모이고 카드마다 단계 칩이 보인다

#### Scenario: 분석 실패 알림
- **WHEN** 엔지니어의 검토가 위험 조건 찾기 단계에서 실패한 상태로 홈을 열면
- **THEN** "<검토 번호> <제목> 분석이 멈췄습니다"와 오류 문장, 멈춘 단계가 든 알림과 검토 상세로 가는 "오류 내용 보기"가 보이고, 재시도는 잠겨 있으며, 닫으면 알림이 사라진다

#### Scenario: 팀 공유와 행사 예시
- **WHEN** 홈의 팀 공유를 보면
- **THEN** 팀 업무에 사용자마다 하는 일(승인자는 결재, 담당자는 협조 요청)이 보이고, 공지사항 탭과 행사 영역은 예시 띠와 함께 열고 넘길 수 있다

### Requirement: 제품표 화면
화면은 제품표를 제품군 탭과 검색으로 보여 주고, 빈 칸과 팀 가정 값을 구분해 표시하며, 제품을 고르면 전체 칸·값의 출처·판정에 쓰인 곳·제안 포인트·현장 이력을 보여 줘야 한다(SHALL). 두 제품을 골라 칸을 나란히 비교할 수 있어야 한다(SHALL). 고치기 동작은 두지 않는다.

#### Scenario: 제품 상세
- **WHEN** 엔지니어가 제품표에서 판정에 쓰인 제품을 누르면
- **THEN** 오른쪽에 그 제품의 칸, 출처, "판정에 쓰임 n"과 실행별 줄이 보이고 줄을 누르면 그 검토가 열린다

#### Scenario: 두 제품 비교
- **WHEN** 엔지니어가 두 제품을 골라 비교를 누르면
- **THEN** 두 제품의 같은 칸이 한 줄씩 나란히 보이고 빈 칸은 "비어 있음"으로 보인다

### Requirement: 판정 규칙 화면
화면은 비교 방향, 항목 이름, 위험 표현 사전을 탭으로 보여 주고, 줄마다 쓴 횟수를 보여 주며 검색할 수 있어야 한다(SHALL). 고치기 동작은 두지 않는다.

#### Scenario: 규칙 검색
- **WHEN** 엔지니어가 비교 방향 탭에서 "정격 전류"를 검색하면
- **THEN** 그 항목의 규칙 줄만 방향, 시간 조건, 쓴 판정 수와 함께 보인다

### Requirement: 판정 탭 한꺼번에 확정
검토 상세 판정 탭은 줄 고르기 칸과, 고른 줄이 있으면 "n줄 선택 · 제안대로 확정" 띠를, 고른 줄이 없고 확정하지 않은 준수 판정이 있으면 "준수 n줄 모두 확정" 띠를 보여야 한다(SHALL). 담당자 확인 단계가 아니면 두 띠를 보이지 않는다.

#### Scenario: 고른 줄 확정
- **WHEN** 엔지니어가 판정 2줄을 고르고 "제안대로 확정"을 누르면
- **THEN** 두 줄이 확정됨으로 바뀌고 "판정 2줄을 제안대로 확정했습니다." 알림이 보인다

#### Scenario: 준수 모두 확정
- **WHEN** 확정하지 않은 준수 판정이 있는 검토에서 "준수 n줄 모두 확정"을 누르면
- **THEN** 띠가 사라지고 준수 판정은 모두 확정됨이다

### Requirement: TBE 준수표 화면
시스템은 검토 상세 머리의 "TBE 준수표" 단추로 TBE 준수표 화면을 열고, 판정 기준·넣을 줄·항목 언어 선택, 요약(넣는 줄, 준수, 일탈, 질의, 확인 필요, 그중 후보, 위치 없어 뺀 줄), 미리보기 표, "엑셀 내려받기"를 보여야 한다(SHALL). 판정 기준 "제출본 v1"은 승인된 실행에서만 고를 수 있다. 제출본 탭의 "이 판정으로 TBE 준수표 받기"도 이 화면을 연다.

#### Scenario: 넣을 줄 바꾸기
- **WHEN** 엔지니어가 TBE 준수표 화면에서 "확정한 줄만"을 고르면
- **THEN** 미리보기와 넣는 줄 수가 확정한 줄만으로 바뀌고 파일 이름이 "…_확정만.xlsx"가 된다

#### Scenario: 엑셀 내려받기
- **WHEN** "엑셀 내려받기"를 누르면
- **THEN** .xlsx 파일이 내려받아지고 "…를 내려받았습니다 (n줄)." 알림이 보인다

### Requirement: 데이터시트 채우기 화면
시스템은 검토 상세 머리의 "데이터시트 채우기" 단추로 데이터시트 화면을 열고, 데이터시트 고르기, 요약(제출할 칸, 채움 · 확정, 채움 · 후보, 확인 필요), 채움 막대, 보기 거르기(전체 / 후보 / 확인 필요 / 확정), 표, "엑셀 내려받기"를 보여야 한다(SHALL). 후보 줄의 "확정"은 담당자 확인 단계의 엔지니어만 누를 수 있고, 누르면 그 칸이 확정으로 바뀐다. "영업에 넘기기"는 잠근다.

#### Scenario: 칸 확정
- **WHEN** 엔지니어가 후보 줄의 "확정"을 누르면
- **THEN** 그 줄 상태가 확정이 되고 "칸 n … 값을 확정했습니다." 알림이 보이며 채움 · 확정 수가 1 늘어난다

#### Scenario: 확인 필요만 보기
- **WHEN** 보기에서 "확인 필요"를 고르면
- **THEN** 채운 값이 빈 줄만 보인다

### Requirement: 예시 화면
시스템은 백엔드 기능이 없는 메뉴 화면(로그인, 사업 현황·상세, 입찰 이력·상세, 표준 문구, 정답지·채점, 팀 현황, 공지사항, 시스템 공지, 자료실, 설정)을 목업 레이아웃 그대로 고정 예시 데이터로 보여야 하고(SHALL), 로그인을 뺀 화면은 맨 위에 "예시 화면 · 실제 데이터와 연결되지 않음" 띠를 보여야 한다(SHALL). 로그인은 앱 틀 밖이라 목업처럼 띠를 두지 않는다. 예시 화면의 동작은 저장하지 않아야 하며(MUST NOT) 다시 열면 처음 상태다. 입찰 금액과 가격 평가는 가린다.

#### Scenario: 예시 띠
- **WHEN** 왼쪽 메뉴에서 "입찰 이력"을 열면
- **THEN** 목업과 같은 입찰 이력 표와 "예시 화면 · 실제 데이터와 연결되지 않음" 띠가 보이고 서버의 검토 API를 부르지 않는다

#### Scenario: 저장하지 않음
- **WHEN** 예시 화면에서 값을 바꾸는 동작(예: 공지 읽음, 설정 바꾸기)을 하고 화면을 다시 열면
- **THEN** 처음 상태로 보인다

#### Scenario: 금액 가림
- **WHEN** 입찰 이력이나 입찰 상세를 열면
- **THEN** 금액 칸은 숫자 대신 "영업 권한 필요"로 보인다

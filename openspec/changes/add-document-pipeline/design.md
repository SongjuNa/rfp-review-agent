# Design

## Context

입력은 `data/private/rfp_docx/`의 docx 22개. 원본에는 제목 스타일이 거의 없고, 데이터시트 표가 Word 표 여러 개로 쪼개져 있다(파일 1 TS-115-GIS는 표 4개). 가장 긴 문서는 파일 2(약 1.4 MB 텍스트). 같은 폴더의 추출 txt 22개는 줄 번호 기준(추적표 v3의 "N행")이 되므로, 원문 위치의 줄 번호는 txt와 맞아야 한다.

## Goals / Non-Goals

**Goals:**
- 파일 1 하나로 ①~⑥이 끝까지 돌고, 수용 기준이 자동 테스트로 확인된다.
- AI 없이도 코드 규칙 부분(구조, 표, 값, 후보 고르기)은 결정적으로 동작한다.

**Non-Goals:**
- 22개 전체 정확도 측정(11-05 시험 측정에서).
- 화면(4단계 change).

## Decisions

- **파서 선정은 첫 작업.** 후보는 python-docx(표 셀 병합 접근 가능)와 docx2python. 기준: 파일 1의 TS-115-GIS 표 4개를 행·칸 그대로 읽는지, 병합 셀을 반복 없이 읽는지, txt 줄 번호와 단락을 맞출 수 있는지.
- **LangGraph 노드 = 업무 흐름 단계.** classify → structure → extract → type_tag → normalize → risk. 각 노드는 결과를 DB에 쓰고 실행 상태(`review_run.graph_state`)에 다음 단계만 적는다. 노드 안에서 코드 규칙을 먼저 돌리고, AI는 규칙이 못 정한 줄만 받는다.
- **AI 호출 계약.** 절 단위 입력, JSON 스키마로 응답 검증, 실패하면 2회 재시도 후 실행을 FAILED로. 프롬프트·모델 이름·사전 판을 실행에 기록한다.
- **원문 위치.** `source_location`에 txt 기준 줄 번호를 저장하고, docx 단락·표 위치와의 대응표를 구조 나누기 단계에서 만든다.

## Risks / Trade-offs

- docx와 txt 줄 번호가 어긋날 수 있다 → 대응표를 만들고, 수용 기준에 나오는 줄 번호(7459, 7419, 8238 등)를 테스트 고정점으로 쓴다.
- 외부 AI 전송 허용(Q6)이 아직 [확인 필요] → 가림 표시 상태 그대로만 보낸다. 허용 전에는 AI 노드를 끈 채로 코드 규칙만 시험할 수 있게 한다.

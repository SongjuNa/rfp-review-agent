# Proposal

## Why

문서의 묶음·종류는 지금 검토 등록 화면에서 분석 전에 한 번만 정한다(`add-document-confirm`, 안 1). 등록할 때 잘못 고르면
(2026-10-29 시험: 수학계획서를 "요구 사양서 · 묶음 A"로 골라 판정 대상이 됨) 검토를 새로 등록해 처음부터 다시 돌려야 한다.
실제 RFP 한 건은 약 15분과 AI 비용이 든다. 묶음은 판정할지 말지를 정하므로(CR-09) 틀리면 결과가 통째로 틀어진다.
확정은 사람이 한다는 원칙(CR-08, FR-10)에 맞게, 분석이 끝난 뒤에도 엔지니어가 검토 상세에서 고치고 판정만 다시 할 수 있어야 한다.
2026-10-29 minjeong 결정: `add-document-confirm`에서 미뤄 둔 안 2를 이 change로 만든다.

## What Changes

- 검토 상세 문서 표 창에서 엔지니어가 문서마다 묶음(A~D)과 문서 종류를 고치고 사유를 적어 저장할 수 있다. 결재 상신 전(담당자 확인 단계)에만 된다.
- 고친 값은 그 검토에만 적용된다. 같은 파일을 쓰는 다른 검토와 문서 목록은 바뀌지 않는다.
- 묶음이 바뀌면 그 검토의 판정을 다시 만들고(이전 판정은 현재가 아님으로 남김) 뒤 단계(검산·보증값·손실·목록·제안·담당 전달)를 다시 만든다. 문서를 다시 읽거나 AI를 다시 부르지는 않는다.
- 문서 종류만 바뀌면 다시 판정하지 않는다.
- 고친 이력(이전 값, 바뀐 값, 사유, 고친 사람, 시각)을 남기고 문서 표에서 보인다.
- 글자를 읽지 못한 문서는 판정 묶음(A·B)으로 바꿀 수 없다.

## Non-Goals

- 문서 다시 읽기(구조·추출 다시 하기). 문서 종류는 추출에 쓰지 않으므로 필요 없다.
- 결재 상신 뒤나 승인 뒤 고치기.
- 문서 목록(document_catalog) 고치기, 검토에 문서 더하기·빼기.

## Impact

- 명세 `document-intake`: "분석 뒤 문서 분류 고치기" 추가.
- 명세 `review-workspace`: "검토 상세 문서 표" 바꿈(고치지 않는다 → 고칠 수 있다), "문서 표에서 분류 고치기" 추가.
- DB: 마이그레이션 0014 — `run_document`에 검토별 묶음·종류 칸, 고친 이력 표 `document_class_edit`.
- API: `PUT /api/runs/{run_id}/documents/{document_id}/classification`, `GET /api/runs/{run_id}/documents` 응답에 원래 값과 마지막 고친 이력. 화면 타입 다시 생성.
- 화면 SCR-08 문서 표 창. 목업 v4.57에 없는 동작이라 `SCR-08_공유.md`에 남긴다.
- 관련 FR-01·FR-10, CR-08·09·11.

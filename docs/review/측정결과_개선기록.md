## 줄마다 한계

- **1**: 100줄 정답은 Claude 초안입니다. 사람이 확인한 22줄은 일부러 어려운 줄을 많이 넣은 표본이라 정확도 자체(82 %)를 전체 수치로 읽으면 안 됩니다. 다만 같은 줄에서 전후를 비교했으므로 개선 방향은 믿을 만합니다.
- **2**: AI를 끄고 잰 값입니다. 정답(공급사 표시 줄)과 규칙의 정의가 비슷해 100 %가 나오기 쉬운 구조입니다. 지금 코드로 AI를 켠 재측정은 아직 없습니다.
- **2와 4가 이어지는 점**: 같은 C1 작업에서 입찰 서식 처리기는 "서식 작성 안내" 18줄을 요구사항에서 빼 작성 규칙으로 옮겼습니다(표 밖 요구 문장 62 → 44). 그런데 4번 사람 확인에서는 두 사람 모두 서식 작성 안내를 요구사항으로 봤습니다. 이 규칙이 맞는지는 팀 결정이 필요합니다.
- **3**: 문서 2건(파일 1·18)으로만 비교했습니다. 위험 설명·검증 에이전트는 두 문서에 위험 후보가 없어 재지 못했습니다.
- **4**: 사람 2의 답이 Claude 초안(유형 30/30)·Lite(요구사항 18/18)와 완전히 같아, AI를 참고하지 않았는지 확인이 필요합니다. 확인한 두 사람은 입찰 실무자가 아닙니다.
- **6**: "전" 값은 잰 숫자가 아니라 기록된 관찰이고, 코드 판도 다릅니다.

## 테스트에서 배운 것

1. **AI가 정한 정답으로 AI를 채점하면 결론이 뒤집힐 수 있다.** 4번에서 Claude 기준으로는 3.8이 크게 앞섰지만, 사람 기준으로는 반대였습니다. 그 뒤로 모델 선택 근거는 사람 확인 결과(3번 유형)와 코드 검사(문장 초안, 판정 건수)로만 둡니다.
2. **정답 기준이 모호하면 모델 비교가 아니라 정의 차이를 재게 된다.** "요구사항"에 서식 작성 안내를 넣을지가 사람과 시스템 사이에 달랐습니다.
3. **놓친 줄을 상태별로 나눠 보니 원인이 AI가 아니라 코드 규칙이었다.** 2번은 모델을 바꾸지 않고 규칙만 고쳐 K1을 올렸습니다.

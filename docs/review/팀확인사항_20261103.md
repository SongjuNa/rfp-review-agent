## 1. 정답지의 경계 4줄

### 무엇이 문제인가
합성 RFP 28 정답지(`data/seed/answer_keys/synthetic_rfp28_req.csv`, Claude 초안 · 사람 확인 전)는 아래 4줄을 **요구사항**으로 적었습니다. 그런데 AI를 켜면 AI가 이 4줄을 **작성 규칙**(응답을 어떻게 쓰라는 안내)으로 봅니다. 둘 다 말이 됩니다.

| 줄 | 위치 |
|---|---|
| "The Procuring Entity requests proposals … Each bidder shall identify eligible products, state compliance with every mandatory requirement, provide objective evidence, and complete the product-response and evaluation columns …" | 1장 |
| "The product master is a procurement baseline … Where a comparison value is marked as assumed, it must be replaced with verified manufacturer data in the bidder response." | 1장 |
| "Clause-by-clause compliance statement; "Comply", "Exception", or "Not applicable" is required." | 2장 필수 제출물 |
| "The bidder shall complete one response row per offered product. A numeric or text response without a cited source is not accepted as evidence." | 4장 |

### 고르면 바뀌는 것 (파일 28, 같은 분석 결과로 채점)
| | 안 A: 요구사항 (지금) | 안 B: 작성 규칙 |
|---|---|---|
| AI 끔: 재현율 K1 / 정확도 K2 | 100 % / 97.0 % | 100 % / 91.0 % |
| AI 켬: 재현율 K1 / 정확도 K2 | 93.8 % / 100 % | 100 % / 100 % |
| 정답지 요구사항 줄 수 | 65 | 61 |

### 추천: 안 A (요구사항으로 둔다)
- 네 줄 모두 지키지 않으면 입찰이 불리해지는 입찰자 의무입니다(준수 표시, 출처 없는 응답 불인정, 가정값 바꾸기).
- 엔지니어가 놓치면 안 되는 줄을 정답에 두어야, AI가 빼는 경우를 숫자(AI 켬 K1 93.8 %)로 계속 볼 수 있습니다.
- 안 B는 AI 켬 점수가 100 %로 좋아 보이지만, 그 대신 AI 끔의 정확도가 내려갑니다(같은 줄을 "틀리게 뽑음"으로 셈).

### 반영 방법
- 안 A: 정답지를 사람이 확인한 것으로 다시 넣기만 하면 됩니다. "Claude 초안"이 "사람"으로 바뀝니다.
  `cd backend && uv run rfp-db load-answer-key ../data/seed/answer_keys/synthetic_rfp28_req.csv --name "합성 RFP 28 요구사항" --kind REQ --doc RFP_Product_Master_Evaluative_EN_With_Product_Switch --human`
  (유형 정답지도 같은 방법으로 `--human`. 고칠 줄이 있으면 CSV를 고친 뒤 넣습니다.)
- 안 B: CSV에서 4줄을 빼고 위와 같이 넣습니다. 평가 명세의 기준 점수 시나리오와 시험 숫자를 함께 바꿉니다(제가 합니다).

## 2. 파일 1 견적표 사양 문장

### 무엇이 문제인가
명세 `bid-outputs` "일탈·질의 목록"에 남은 [확인 필요]입니다. 실제 RFP 파일 1의 견적표(가격표) 행에 있는 사양 문장("230kV, 3-pole, 4000A, 50kA …", 1784행)은 요구사항으로 뽑지 않아, 4,000 A 일탈 묶음의 원문 위치가 3곳이 아니라 2곳입니다. 가격표 사양 추출은 별도 change로 미뤄 두었습니다.

### 고를 수 있는 안
- 안 A: 닫는다. 팀이 실제 RFP 대신 합성 RFP로 시연·평가하기로 했고(2026-11-02), 합성 RFP에는 견적표 사양 행이 없습니다. 명세의 [확인 필요]를 "범위 밖(실제 RFP 미사용)"으로 바꿉니다.
- 안 B: 가격표 행의 사양 문장을 요구사항으로 뽑는 change를 만든다. 가격 계산은 범위 밖이라 사양 문장만 뽑습니다. 실제 RFP에서만 효과가 있습니다.

### 추천: 안 A (닫기)
시연·평가 데이터에 해당 줄이 없어 효과를 보일 곳이 없습니다. 실제 RFP를 다시 쓰게 되면 그때 안 B를 합니다.

## 3. 추정 비용의 모델 단가

### 무엇이 문제인가
명세 `review-run` "실행 기록 응답"에 남은 [확인 필요: 모델 단가]입니다. 실행 기록과 AI 사용량의 추정 비용은 다음 팀 가정 단가로 계산합니다(`backend/src/rfp_agent/pipeline/run_log.py`).
- gemini-3.8-flash: 1M 토큰당 입력 $0.50, 출력·생각 $4.00
- 1달러 = 1,500원
- 근거: 2026-10-25 파일 1 실측 1건(입력 73,556 · 출력 28,775 · 생각 77,778 토큰 ≈ 680원)에 맞춘 값

최근 측정의 추정 비용은 합성 RFP 28 한 건에 84원·145원이었습니다. 실제 청구서와 대조한 적은 없습니다.

### 고를 수 있는 안
- 안 A: 지금 값을 유지하고, Google 결제 화면에서 11-02~11-03 청구 금액을 한 번 확인해 추정과 크게 다르지 않으면 [확인 필요]를 닫는다.
- 안 B: 공식 가격표 값으로 바꾼다(누가 확인해 알려 주면 코드 한 줄과 명세를 바꿉니다).

### 추천: 안 A
발표에서 "건당 수백 원"이라고 말할 근거가 되므로, 청구서 한 번 대조로 충분합니다. 결제 화면은 키를 가진 사람만 볼 수 있습니다.

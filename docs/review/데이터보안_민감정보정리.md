5. **발표·공개 자료에는 고객 원문의 식별 정보를 옮기지 않습니다** (기획서 5-6).

## 3. AI 사용 방식 (NFR-07)

| `RFP_AI_MODE` | 보내는 곳 | 비고 |
|---|---|---|
| `gemini` (기본) | Google Gemini | 키가 없으면 자동으로 `off`와 같음 |
| `local` | 사내 서버의 OpenAI 호환 주소만 | 주소·모델이 비면 `off`와 같음 |
| `off` | 없음 | 키가 있어도 보내지 않음. 판정과 숫자는 같게 나옴(CR-01) |

- 지금 방식과 외부 전송 여부는 상태 점검(`/api/health`의 `ai_mode`), 검토 등록 화면, 실행 기록 화면에 보입니다.
- Docker로 실행할 때 이 설정이 백엔드에 전달되지 않던 문제를 고쳤습니다(`docker-compose.yml`, `.env.example`). 고치기 전에는 Docker에서 `off`로 바꿔도 Gemini로 보냈습니다. **확인함(11-02): `.env`에 `RFP_AI_MODE=off`를 넣고 `docker compose up -d backend`를 실행하니, 키가 있어도 `/api/health`가 `"ai_mode":"OFF"`였습니다.**

## 5. 로그 가림 (NFR-06): 아직 구현 안 함

- 명세의 "로그 원문의 고객사명·연락처·단가 가림"은 **구현하지 않았습니다. 다음 단계**로 둡니다.
- 지금 위험은 작습니다. 백엔드 로그는 12곳이고 대부분 오류 종류만 남깁니다. AI 요청·답 원문은 로그에도 DB에도 저장하지 않습니다.
- 남은 빈틈: AI 답의 형식이 틀렸을 때 남기는 경고(`llm/client.py`)에 AI 답 일부, 즉 RFP 문장이 섞일 수 있습니다.
- 다음 단계에서 할 일: 그 경고에서 원문을 빼고 오류 종류만 남기기, 로그에 이메일·전화번호·금액 모양이 있으면 가리기.

## 6. 저장소 공개 상태와 git 기록

- 저장소는 **평소 비공개**입니다. 제약 때문에 잠시 공개로 바꿨고, 다시 비공개로 되돌릴 예정입니다.
- 커밋 `319eaa9`에 고객 RFP 줄(파일 1 데이터시트 100줄과 설비 위치)이 든 실험 CSV 3개가 들어갔고, `3160978`에서 지우고 `.gitignore`에 넣었습니다. **두 커밋이 모두 main에 있어서, 공개 상태인 동안에는 git 기록으로 볼 수 있습니다.** 비공개로 되돌리면 외부 노출은 막히고, 계속 공개해야 한다면 기록에서 그 파일을 지우는 작업(기록 다시 쓰기)이 필요합니다.
- 저장소 문서 일부(모델 검토 문서, 기획서 등)에 고객 RFP 문장을 짧게 인용한 곳이 있습니다. 비공개 저장소 안의 팀 문서로 보고 두되, 발표 자료에는 옮기지 않습니다.

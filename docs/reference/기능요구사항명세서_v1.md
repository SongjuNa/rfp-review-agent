### 1-2. 이 명세서를 읽는 법

기능마다 같은 7칸을 적었습니다.

| 칸 | 내용 |
|---|---|
| ① 목적 | 이 기능이 엔지니어의 어떤 일을 덜어 주나 |
| ② 입력 | 무엇을 받나 |
| ③ 출력 | 무엇을 어떤 칸으로 내나 |
| ④ 규칙 | 누가(코드 / AI / 사람) 어떤 규칙으로 하나 |
| ⑤ 예외 | 값 없음, 가림 표시, 단위 다름 등에서 어떻게 하나 |
| ⑥ 수용 기준 | Given(이런 입력에서) – When(이 기능이 돌면) – Then(이렇게 나와야 한다). 개발 완료 판단과 시험에 씀 |
| ⑦ 관련 사례·지표 | 추적표 v3의 사례 번호, 기획서 2-2의 지표 |

## 2. 공통 규칙

모든 기능에 똑같이 적용합니다.

| ID | 규칙 | 내용 |
|---|---|---|
| CR-01 | 역할 나누기 [결정] | **숫자와 판정 규칙은 코드, 문장 읽기와 쓰기는 AI, 확정은 사람.** AI는 숫자 계산, 판정, 후보 고르기, 분기 선택, 확정을 하지 않음 |
| CR-02 | 근거 묶음 [결정] | 시스템이 만드는 모든 값은 `{값, 원문 위치, 신뢰도, 가정 여부}`를 함께 저장. 원문 위치가 없는 값은 결과로 내보내지 않고 "확인 필요" |
| CR-03 | 원문 위치 | `파일 번호 + 절(또는 표 이름) + 행 번호(또는 표의 행·칸)`. 같은 내용이 여러 곳에 있으면 위치를 모두 저장 |
| CR-04 | 지어내지 않음 [결정] | 없는 값은 비워 두고 "확인 필요". AI가 빈칸에 값을 만들지 않음 |
| CR-05 | 가림 표시 | [REDACTED] 등은 "값 없음"으로 저장하고 추측하지 않음 |
| CR-06 | 팀 가정 표시 | 가정 값(변압기 손실값, 제품표의 팀 합성 비교값 등)이 들어간 결과에는 화면·산출물에 항상 "팀 가정". 판정·보증값은 그 결과에 쓴 제품 칸이 팀 가정일 때 표시 |
| CR-07 | 숫자 일치 검사 | AI가 쓴 문장 속 숫자는 자리표시자로 두고 코드가 채움. 채운 뒤 근거 값과 다시 대조, 다르면 경고. 자리표시자 뒤 조사(은/는, 이/가, 을/를, (으)로, 과/와)는 채운 값의 끝 글자에 맞춰 코드가 고름(예: "GIS-145-40은") [제안] |
| CR-08 | 후보까지만 [결정] | 위험 조건, 일탈, 질의, 보증값, 제안 포인트는 모두 "후보". 확정은 사람(FR-10) |
| CR-09 | 판정 범위 [결정] | 적합성 판정과 보증값 후보 작성은 **묶음 A·B만**. 묶음 C·D는 추출·유형 표시·위험 조건 찾기까지 |
| CR-10 | 단위 환산 안 함 [결정] | 원문 단위 그대로 저장. 단위가 다르면 비교하지 않고 "확인 필요" |
| CR-11 | 재현성 | 같은 입력과 같은 사전·제품표에는 숫자·판정 결과가 늘 같음 |
| CR-12 | AI 오류 | 정해진 횟수만 재시도, 그다음 멈추고 "처리 실패 — 다시 시도". 처리 중인 검토는 사람이 취소할 수 있고(다음 진행 기록 때 멈춤), 실패·취소한 검토는 사람이 "다시 시도"하면 같은 파일·같은 분류로 처음부터 다시 돌리되 이미 처리한 문서는 다시 쓴다(NFR-05) [제안] |

### FR-02 구조 나누기 (Must)

| 칸 | 내용 |
|---|---|
| ① 목적 | 제목 스타일이 없는 문서를 장·절·표·행으로 나눠, 이후 모든 기능이 같은 "한 줄"을 기준으로 일하게 함 |
| ② 입력 | docx 단락·표, FR-01 결과 |
| ③ 출력 | `section` (번호, 제목, 상위 절, 원문 위치), `table` (표 이름, 이어 붙인 원래 표 번호 목록), `table_row` (항목 번호, 상위 항목 번호, 칸 값, 칸 역할: 항목 이름 / 단위 / 요구값 / 보증값 / 공급사 표시) |
| ④ 규칙 | 코드만. 번호 패턴("PART 1", "1.1", "A.", "가.", "1)")으로 절 복원. **쪽 넘김 표 잇기**: 머리글 줄과 표 이름(예: TS-115-GIS)이 같고 항목 번호가 이어지면 한 표로. **반복 머리글 제거**: 쪽마다 반복되는 "Technical Data Sheet…" 줄과 제목 줄은 항목이 아님. **하위 항목 연결**: 번호 없는 "- …" 줄은 바로 위 번호 항목의 하위(예: 20-1). **칸 역할 인식**: "Employer's Requirement" → 요구값, "Warranted Data" → 보증값, "C/D/E" → 공급사 표시 (칸 이름 사전 사용). **목차와 본문 구분**: 같은 제목이 두 번 나오면 앞쪽(목차)은 표시만 |
| ⑤ 예외 | 번호가 끊기면 앞뒤 절에 붙이고 "구조 확인 필요". 칸 역할을 못 찾으면 그 표는 "칸 확인 필요" |

| ⑦ 관련 | 사례 1, 8, 11. K1·K4의 바탕 |

### FR-03 요구사항 추출 (Must)

| 칸 | 내용 |
|---|---|
| ① 목적 | 약 11,540줄의 요구사항 후보를 엔지니어가 처음부터 읽지 않아도 되도록 한 줄씩 뽑음 |

| ⑥ 수용 기준 | **Given** 비용 영향 유형 줄(손실 환산 조항) / **Then** 견적 담당 "내 할 일"에 1건<br>**Given** 채택된 제안 포인트 1건 / **Then** 영업 담당에게 전달 기록 1건<br>**Given** 품질 담당 요청 1건이 걸린 판정을 엔지니어가 확정 / **Then** 품질 담당 주소로 메일 1통, 요청은 "메일 보냄"<br>**Given** 이미 보낸 요청 / **When** 다른 판정 확정 / **Then** 다시 보내지 않음<br>**Given** 후보 칸이 없는 데이터시트 / **When** 엔지니어가 [영업에 넘기기] / **Then** 영업 주소로 엑셀 1통, 넘긴 기록 1건<br>**Given** 후보 칸이 남은 데이터시트 / **Then** 넘기지 않고 "후보 n칸을 먼저 확정"<br>**Given** 결재 승인된 검토 / **When** 인계 패키지 보내기 / **Then** zip 1개(일탈 목록·질의서·TBE·데이터시트)를 붙인 메일 1통 |

| ③ 출력 | 상업 조건 탭: 조항 종류별 비용 조건(원문, 값 원문 그대로, 원문 위치, 부담 표시, 위험 표시, 담당 = 견적, 협조 요청 상태)과 기술 판단에서 생긴 상업 영향(손실 환산 가산액·팀 가정, 일탈 후보 가격 영향 확인) |
| ④ 규칙 | 코드만(CR-01). 유형 규칙표에 비용 영향 규칙(지체상금, 책임 한도, 하자 보증, 이행 보증서, 지급 조건, 가격 유효 기간, 인도 조건, 통화·환율, 예비품, 특수 공구, 운반·포장, 시험 입회, 설치 감독, 교육, 무상 공급)을 더하되 시험·제조사 자격 규칙보다 뒤 순위로 둬 그 줄의 주 유형·담당은 바꾸지 않음 [제안]. 조항 종류는 먼저 걸린 것 하나. 같은 조건 반복은 FR-11과 같이 한 줄로 묶음. **금액 계산·합산·단위 환산 없음**(CR-10). 묶음 제한 없음(판정이 아니라 CR-09 대상 아님). 모든 줄은 후보(CR-08) |
| ⑤ 예외 | 원문 위치가 없는 줄은 내지 않음(CR-02). 값이 없으면 빈칸. 손실 환산 가산액이 없으면 "확인 필요". 상업 조항이 요구사항으로 추출되지 않은 문서는 표가 빔 [확인 필요] |
| ⑥ 수용 기준 | **Given** "Liquidated damages shall be 0.5 % of the Contract Price per week" / **Then** 주 유형 = 비용 영향, 종류 = 지체상금<br>**Given** "Type Test shall be witnessed by the Employer" / **Then** 주 유형 = 시험, 보조 유형 = 비용 영향, 종류 = 시험 입회<br>**Given** "Special tools shall be supplied at no additional cost" / **Then** 종류 = 특수 공구, "계약상대자 부담"<br>**Given** 하자 보증 값 "24 months" / **Then** 값 칸에 "24 months" 그대로 |
| ⑦ 관련 | 차별화 아이디어 C1(10-23, 10-24 보강). minjeong 결정 10-31(2단계 새 개발). 보내기는 FR-11 협조 요청 메일. 가격표 품목 연결(C4)·숨은 무상 공급 목록(C2)은 만들지 않음 |

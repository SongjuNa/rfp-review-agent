- 연결 요구사항: 차별화 아이디어 C1(비용 조건 요약, 팀 결정 대기), `review-workspace` 상업 조건 예시 탭·예시 탭
- 기준 목업: `Spec2Win_목업_v4.57.html#Detail` 상업 조건 탭 (`#comm`)
- 구현 방식: 예시 화면 (`update-review-screens` 묶음 8). 목업 데이터를 옮기고 저장하지 않는다 (`_공통규칙.md` 6장)
- 사용 API: 없음
- 예정 API: 상업 조항 목록(조항 종류, 요약, 원문, 원문 위치, 위험 표시), 전달·회신 상태. C1 결정 뒤 별도 change

## 화면 구성

| 영역 | 보이는 항목 | 비고 |
|---|---|---|
| 예시 띠 | "예시 화면 · 실제 데이터와 연결되지 않음" | 탭 맨 위 |
| 머리(`.sech`) | "RFP 조항 9 · 기술 판단 영향 3 · 미전달 n", "n건 선택", "골라서 전달" | 고른 것이 없으면 단추가 눌리지 않는다 |
| 안내(`.rdi`) | 목업 문장 그대로 | |
| RFP의 상업 조항 표(`.cmt`) | 고르기, 조항 종류(+위험 표시), 요약·원문·회신, 원문 위치, 담당(견적 담당/영업 담당), 상태(미전달·전달·확인·회신)와 시각 | 전달한 줄은 고르기·담당이 잠긴다 |
| 기술 판단에서 생긴 상업 영향 표 | 고르기, 종류, 요약과 연결("판정 · …"/"손실 환산" →), 담당, 상태 | 예시라 연결은 이동하지 않는다 |
| 아래 문장(`.cmfoot`) | "전달한 항목은 협조 요청 현황에서 회신을 확인할 수 있습니다." | 협조 요청(SCR-13)으로 이동 |
| 알림(`.ltoast`) | "상업 조건을 전달했습니다: 견적 담당 n건, 영업 담당 n건" | 3초 뒤 사라짐 |

## 화면 상태

- 화면을 다시 열면 처음 예시 상태로 돌아온다 (저장 안 함).

## 수용 기준 (Given / When / Then)

- **Given** 검토 상세, **When** 미전달 두 줄을 고르고 "골라서 전달", **Then** 두 줄 "전달", 고르기 잠김, 알림, 미전달 수 2 줄어듦. (상업 조건 골라서 전달 예시)
- **Given** 전달한 뒤, **When** 화면을 다시 열면, **Then** 처음 미전달 수로 돌아온다. (예시 탭)

# 화면 명세: SCR-08-8 제출본 탭

- 연결 요구사항: FR-10(승인 뒤 확정), `review-workspace` 제출본 탭
- 기준 목업: `Spec2Win_목업_v4.57.html#Detail` 제출본 탭 (`#subm`), 머리 단추 "제출본 v1 확정"
- 구현 방식: 실제 (`update-review-screens` 묶음 10). 새 API 없이 승인 기록과 판정 수로 보인다
- 사용 API: `GET /runs/{id}/approval`(`approval.decision`·`decided_at`·`approver`), `GET /runs/{id}`(`judgments`), 판정 수(`X-Total-Count`)
- 예정 API: TBE 준수표 내려받기 (`add-tbe-export`)

## 화면 구성

| 영역 | 보이는 항목 | API 칸 | 비고 |
|---|---|---|---|
| 머리(`.sech`) | 제목, 안내, "이 판정으로 TBE 준수표 받기" | — | TBE 내려받기 전까지 잠김(마우스를 올리면 이유) |
| 표(`.subt`) | 버전 v1, 확정(승인 시각), 결재자, 판정 n줄, 일탈 n · 질의 n, 첨부 2개, "현재 제출본" | `decided_at`, `approver`, `judgments`, 판정 수 | 승인된 실행에서만 |
| 빈 안내(`.subempty`) | "아직 확정된 제출본이 없습니다. …" | — | 승인 전 |
| 머리 단추(판정 탭) | "제출본 v1 확정" (잠김) | `stage = APPROVED` | 목업 apBtnLabel |

승인된 실행은 담당자 확인 단계가 아니라서 판정을 고칠 수 없다. 그래서 승인 시점의 판정이 그대로 제출본이고 사본을 따로 저장하지 않는다.

## 수용 기준 (Given / When / Then)

- **Given** 승인된 실행, **When** 제출본 탭을 열면, **Then** v1 줄과 "현재 제출본", 머리 단추 "제출본 v1 확정". (승인된 실행의 제출본)
- **Given** 담당자 확인 단계, **When** 제출본 탭을 열면, **Then** "아직 확정된 제출본이 없습니다" 안내. (승인 전 제출본 없음)

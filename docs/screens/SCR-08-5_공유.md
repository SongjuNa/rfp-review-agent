# SCR-08-5 입찰 영향 탭·머리글 비교 제품: 목업과 다르게 만든 것 (공유)

| # | 목업 | 앱 | 이유 |
|---|---|---|---|
| 1 | 유리한 점 제목이 짧은 이름("단시간 견딤 시간 3배") | 근거 줄("요구 40 kA (1초) · 제품 … · 여유 시간 3배")을 제목으로 | 제안 포인트에 제목 칸이 없다. 근거를 먼저 보여 준다 (CR-02) |
| 2 | "제외" 링크, 사유 없음 | "버림" + 사유 입력 | 상태 라벨은 API(`DISCARDED` 버림). 버리기는 사유가 필요하다(`POST /actions` DISCARD) |
| 3 | 유리한 점 문장 고치기 없음 | 없음 (같음). 예전 화면의 문장 고치기는 뺌 | 목업대로. 문장 고치기가 필요하면 다음 change에서 |
| 4 | 불리한 점에 원문 위치 없음 | 위치 한 줄 추가 | 근거 위치 (`_공통규칙.md` 4장) |
| 5 | 탭에 공학 검산 결과 없음 | 없음 (예전 화면의 검산 목록을 뺌) | 목업대로. 검산 위반은 질의 후보로 판정 탭과 질의서 초안에 나온다 (FR-12) |
| 6 | 머리글 "115 kV 비교 제품" 하나 | 머리글 아래 "비교 제품" 칸에 설비 묶음(표)마다 한 줄(묶음 이름 \| 후보 단추). 묶음이 4개보다 많으면 접어 두고 "설비 n개 · 지금 제품" 요약만 (2026-10-29 `update-detail-layout`) | 비교 제품은 설비 묶음마다 따로 고른다. 실제 RFP는 묶음이 10개 넘고 후보가 14개인 묶음도 있어 머리글 한 줄에 들어가지 않는다 |
| 7 | 비교 제품 후보에 설계 사례 카드(…-P7) | 판정 코드가 고른 후보만 | 후보는 `selection.candidates`가 정한다 (설계 사례 카드는 비교 제품이 아님) |
| 8 | "문서 추가" 단추 | 없음 | 문서 추가는 실행을 다시 해야 해 범위 밖 (SCR-08_공유 3번) |

e2e는 로컬에 언어 모델 키와 강점 여유가 있는 제품값이 없어 제안 포인트 목록과 후보가 둘인 설비 묶음 응답을 바꿔 끼워 확인한다. 요청 내용(채택·버림·제품 바꾸기)은 그대로 확인한다.

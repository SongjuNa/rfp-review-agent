# SCR-13 협조 요청 현황: 목업과 다르게 만든 것 (공유)

| # | 목업 | 앱 | 이유 |
|---|---|---|---|
| 1 | 요구사항 줄: 짧은 제목("SF6 가스 누설률 카탈로그 값") + 요약 설명 | RFP 원문 문장(80자까지) + 유형 이름 또는 "같은 조건 N곳을 한 건으로 묶음" | 요청은 FR-11이 원문 줄을 그대로 보낸 것이다. 짧은 제목을 만들려면 언어 모델이 써야 하는데, 원문을 바꿔 쓰지 않는다 |
| 2 | 수신자에 사람 이름(예: 품질 담당자 한 명) | "보낸 주소"에 부서 메일 주소 | 요청은 사람이 아니라 부서 주소로 메일이 간다(update-role-handoff-mail) |
| 3 | 재요청 링크·단추가 눌림 | 재요청 대신 [보내기]·[다시 보내기](안 보냄·발송 실패만). 메일을 보낸 요청의 재요청은 없고 "다시 연락 필요"만 보인다 | 같은 요청은 한 번만 보낸다. 재요청 자동 알림은 만들지 않는다 [결정 10-31] |
| 4 | 회신 글(시각 · 내용) | 엔지니어가 적은 회신 요지 한 줄과 시각 | 받은 메일을 읽지 않는다. 회신은 엔지니어가 메일을 보고 요지만 적는다 |
| 5 | 받는 사람 쪽 화면이 없음 | 목업과 같음. 견적·품질·영업 담당은 읽기만 하고, 엔지니어가 상세 창 아래 단추로 "회신 받음 표시"·되돌리기 | 협업 부서는 사내 메일로 받는다(강사님 피드백 10-29, 10-31 결정). 예전 "확인함·처리 끝"은 지움 |
| 6 | 요청하기로 새 요청을 만듦 | 같은 창이지만 예시 띠, 보내면 예시 알림만 | 직접 요청을 만드는 API가 없다 |
| 7 | 내보내기(Excel) | 잠김 | 내보내기는 다음 change에서 만든다 |
| 8 | 미분류 탭에 담당 부서가 없는 요청 | 늘 비어 있음 | FR-11은 견적·품질·영업 유형만 보내고, 엔지니어 몫과 미분류는 검토 화면에 남긴다 |
| 9 | (예전 앱) 엔지니어·승인자의 "내 할 일" 검토 카드 | 이 화면에서 뺌 | 목업 협조 요청 화면에는 없다. 걸린 검토 카드는 홈(SCR-03)에 둔다. API(`GET /tasks`)는 그대로 |
| 10 | 요약 줄 미확인 · 24시간 넘게 미확인 · 확인 | 안 보냄 · 회신 대기 · 24시간 넘게 회신 없음 · 회신 받음 | 메일 발송을 더하면서 "보냈는지"와 "회신 받았는지"를 나눠 보인다 |

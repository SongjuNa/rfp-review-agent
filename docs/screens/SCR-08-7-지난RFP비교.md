# 화면 명세: SCR-08-7 지난 RFP 비교 탭

- 연결 요구사항: `review-workspace` 지난 RFP 비교 예시 탭 (명세서 v1에 없는 기능)
- 기준 목업: `Spec2Win_목업_v4.57.html#Detail` 지난 RFP 비교 탭 (`#cmp`)
- 구현 방식: 예시 화면 (`update-review-screens` 묶음 9). 예시 데이터 `frontend/src/examples/SCR-08-7.ts`
- 사용 API: 없음
- 예정 API: 같은 고객의 지난 검토 목록, 두 검토의 요구를 표준 항목(`item_key`)으로 짝지은 결과와 판정 변화

## 화면 구성

| 영역 | 보이는 항목 | 비고 |
|---|---|---|
| 예시 띠 | "예시 화면 · 실제 데이터와 연결되지 않음" | |
| 머리(`.sech`) | 제목, 안내 문장, "비교 대상" 고르기 | 대상 2개 |
| 지난 입찰(`.cmph`) | 입찰 번호(입찰 이력으로), 사업 이름, 제출일 · 제품, 결과(수주) | |
| 건수 칸(`.cmpk`) | 달라진 요구 · 값 바뀜 · 새로 생김 · 사라짐 | 누르면 그 구분만 거른다(`aria-pressed`) |
| 표(`.tbl`) | 구분 배지, 항목, 지난 RFP, 이번 RFP, 판정 변화(이전 → 이번, 사라짐은 "요구 없음"), 참고 | 사라진 줄은 흐리게 |
| 아래 문장 | "같은 요구 n줄은 판정이 지난번과 같아 숨겼습니다." | |

## 화면 상태

- 비교 대상을 바꾸면 거르기가 "달라진 요구"로 돌아간다. 저장하지 않는다.

## 수용 기준 (Given / When / Then)

- **Given** 지난 RFP 비교 탭, **When** "새로 생김"을 누르면, **Then** 새로 생긴 요구만 남고, 대상을 바꾸면 거르기가 풀린다. (지난 RFP 비교 거르기 예시)

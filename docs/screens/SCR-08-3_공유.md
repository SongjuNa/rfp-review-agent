# SCR-08-3 위험 조건 탭: 목업과 다르게 만든 것 (공유)

| # | 목업 | 앱 | 이유 |
|---|---|---|---|
| 1 | 머리 "포괄 조항 0 · 값 불일치 0" | "포괄 조항 n · 값 불일치 n · 범위 모호 n" | API 위험 종류가 3가지다 (`_공통규칙.md` 2장) |
| 2 | 닫은 줄 배지 "닫음" | "문제 없음" | 후보 상태 라벨은 API를 따른다 (`CLOSED_OK` 문제 없음) |
| 3 | 목업에는 닫은 줄만 있고 열린 줄의 처리 단추가 없음 | 후보 줄 처리 칸에 "위험으로 확정"·"문제 없음"(사유 입력) | 위험 조건은 사람이 확정해야 하는 후보다 (CR-08, FR-10). 목업은 모두 처리한 뒤 모습 |
| 4 | 원문 위치는 글자만 | 누르면 원문 문장을 펼침 | 근거 위치를 누르면 원문을 연다 (`_공통규칙.md` 4장) |
| 5 | "사람이 찾은 특이 요구" 제안이 저장되는 것처럼 동작 | 예시 띠를 붙이고 저장하지 않음, 예시 문장은 합성 | 위험 표현 사전 제안 API가 없다 (`_공통규칙.md` 6장) |
| 6 | "규칙 담당(김민수 수석)" | "규칙 담당" | 직급·규칙 담당 지정이 없다 |
| 7 | 줄 설명은 사람이 쓴 문장 | 닫은 사유 → AI 설명 → 종류별 한 줄 순서로 | 위험 조건에는 사람이 쓴 설명 칸이 없다 |

판정 탭(SCR-08-1)과 같이 원문 위치는 "파일 N" 대신 파일 이름으로 보인다 (`_공통규칙.md` 3장).

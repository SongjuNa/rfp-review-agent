# SCR-11 분석 실패 상세: 목업과 다르게 만든 것 (공유)

| # | 목업 | 앱 | 이유 |
|---|---|---|---|
| 1 | 단계 "분석 실패" | "처리 실패" | 단계 라벨은 API를 따른다 (SCR-06_공유 1번과 같은 결정) |
| 2 | 멈춘 위치 "UPS … · 6.3절 · 412번째 요구사항"과 "멈춘 곳 원문" 카드 | 시각 · 문서 수만, 원문 카드 없음 | 실패할 때 어느 요구사항에서 멈췄는지 저장하지 않는다. 예시 원문을 실제 실패 화면에 섞지 않는다 |
| 3 | 계속하는 방법을 고르고 실행 | 예시 영역(예시 띠), 실행하면 예시 알림만 | 다시 시도 API가 없다. 재시도는 처리 중 자동으로 정해진 횟수만 한다 (CR-12) |
| 4 | 진행 상황: 문서 읽기 → 요구사항 추출 → 제품과 비교·판정 → 위험 조건 찾기 → 입찰 영향 정리 | 문서 읽기 → 위험 조건 찾기 → 제품과 비교·판정 → 일탈·질의 목록 → 입찰 영향 정리 | 실제 처리 순서(위험 조건 찾기가 판정 앞)를 따른다. 요구사항 추출은 문서 읽기 안에서 한다 |
| 5 | 지금 볼 수 있는 것: 일탈 후보 · 질의 후보 · 확인 필요 | 일탈 후보 · 판정 · 위험 조건 | 실행 요약 API에 있는 수만 쓴다 |
| 6 | 처리 기록: 단계마다 끝난 시각, 자동 재시도 1·2·3회 | 시작과 멈춤 두 줄 | 단계별 시각과 재시도 기록을 저장하지 않는다 |
| 7 | 문의용 정보: 오류 코드, 처음 발생, 마지막 재시도, 작업 번호, 위치, 모델 응답 | 작업 번호, 멈춘 단계, 발생, 모델, 오류 | 저장한 값만 |
| 8 | 처리 중 실패는 "멈춤" 문서 표시 | 읽음 / 읽지 못함 / (문서 읽기에서 멈췄고 요구사항이 없으면) 멈춤 | 문서별 실패 위치가 없다 |

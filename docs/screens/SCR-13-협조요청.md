# 화면 명세: SCR-13 협조 요청 현황

- 연결 요구사항: FR-11(유형별 담당자 전달), `role-assignment`(할 일 상태, 협조 요청 메일 발송), `review-workspace` 협조 요청 현황 화면
- 기준 목업: `Spec2Win_목업_v4.57.html#Todo`
- 구현 방식: 실제 + 예시 창 (`update-review-screens` 묶음 13, `update-role-handoff-mail`). 화면 CSS는 목업 Todo CSS 그대로(`frontend/src/mockup/Todo.css`)
- 사용 API: `GET /assignments?role=COST|QUALITY|SALES`(모든 검토의 그 부서 요청, 검토 번호·파일 이름·보낸 기록·회신 기록 포함), `POST /runs/{id}/assignments/send`(엔지니어가 보내기·다시 보내기), `PUT /assignments/{id}`(엔지니어가 회신 받음 표시·되돌리기)
- 메일은 시스템이 보낸다: 엔지니어가 판정을 확정하면(연결된 판정이 모두 사람 확인됨) 아직 안 보낸 요청을 부서별로 한 통씩, 채택한 제안 포인트는 채택할 때. 판정이 없는 요청은 이 화면의 [보내기]
- 예정 API: 직접 요청 만들기, 내보내기(Excel)

## 화면 구성

| 영역 | 보이는 항목 | API 칸 | 비고 |
|---|---|---|---|
| 수신 부서 탭(`.pgtabs`) | 견적 담당 · 품질 담당 · 영업 담당 · 미분류 | `role` | 처음 탭: 견적·품질·영업 사용자는 자기 부서, 그 밖에는 견적 담당. 미분류는 늘 빈 목록 |
| 제목(`.ttl`) | 탭 이름, 내보내기 | — | 내보내기 잠김 |
| 요약 줄(`.sumline`) | 안 보냄 · 회신 대기 · 24시간 넘게 회신 없음 · 회신 받음 | `status`, `mail_sent_at` | 화면을 연 시각 기준 |
| 요청 표(`.tbl`) | 상태(+ 발송 실패·주소 없음 꼬리표), 요구사항(묶음·제안 포인트 꼬리표, 문장, 팀 가정, 유형·묶음 설명, 검토 번호 연결, 원문 위치), 보낸 주소, 보낸 일시, (엔지니어) 보내기·다시 보내기 | `text`, `type_name`, `repeat_count`, `point_kind`, `is_assumed`, `review_no`, `locations`, `file_name`, `mail_to`, `dept_address`, `mail_sent_at`, `mail_error` | 회신 받은 줄은 흐리게. 10·20·50개씩 쪽 나눔. 안 보낸 줄의 주소는 지금 설정된 부서 주소 |
| 요청 상세 창(`.pmw.cw`) | 상태, 문장, 부서 · 주소 / 요청 내용, 팀 가정 안내, RFP 원문(위치 + 문장), 회신(회신 요지 또는 입력 칸) / 관련 검토, 수신 부서, 받는 주소, 보낸 사람, 회신 기한 / 진행 | 위와 같음, `sent_by_name`, `replied_at`, `replied_by_name`, `reply_note` | 회신 기한 = 메일 보낸 날 + 3일(목업 규칙), 지나면 빨강 |
| 상세 창 아래 단추 | Esc로 닫기, 검토 상세 열기, (엔지니어) 보내기·다시 보내기 / 회신 받음 표시 / 회신 받음 되돌리기 | `POST …/assignments/send`, `PUT /assignments/{id}` | 견적·품질·영업 담당은 읽기만 |
| 요청하기 창(`.nwd`) | 예시 띠, 관련 검토, 원문 위치, 요구사항, 수신 부서·수신자, 요청 내용, 회신 기한, 원문 발췌 함께 보냄 | — | 예시. 빈칸이면 목업과 같은 오류 문구, 보내면 "예시 화면이라 보내지 않았습니다" 알림만 |

## 상태

| 할 일 상태 | 화면 상태 | 진행 |
|---|---|---|
| TODO(안 보냄) | 안 보냄(회색). 실패면 "발송 실패", 주소가 없으면 "주소 없음" 꼬리표(빨강) | 만듦 → 메일 보내기 전(또는 발송 실패·주소 없음) |
| DOING(메일 보냄), 24시간 이하 | 회신 대기(파랑) | 만듦 → 메일 보냄 → 회신 대기 |
| DOING, 24시간 넘음 | 24시간 넘게 회신 없음(주황) | 만듦 → 메일 보냄 → 24시간 넘게 회신 없음(다시 연락 필요) → 회신 대기 |
| DONE(회신 받음) | 회신 받음(초록, 줄 흐림) | 만듦 → 메일 보냄 → 회신 받음 |

## 메일

- 제목 `[협조 요청] <검토 번호> <사업명>`, 받는 사람은 부서 주소(`RFP_MAIL_COST`·`RFP_MAIL_QUALITY`·`RFP_MAIL_SALES`).
- 본문: 제출 마감, 회신 기한, 요청마다 [종류](팀 가정) · 요구사항 · 원문 위치. 엑셀 첨부(No., 요청 종류, 요구사항, 원문 위치, 팀 가정, 회신 칸).
- 개발·시연은 Mailpit(<http://localhost:8025>)에서 받은 메일을 본다. 밖으로 나가지 않는다.

## 수용 기준 (Given / When / Then)

- **Given** 품질 담당에게 간 형식시험 요청, **When** 엔지니어가 품질 담당 탭을 고르면, **Then** "안 보냄" 또는 "회신 대기" 줄과 검토 번호, 파일 이름이 든 위치, 상태별 수. (수신 부서별 요청 현황)
- **Given** 메일 보낸 지 24시간이 넘은 요청, **When** 화면을 열면, **Then** "24시간 넘게 회신 없음", 상세 진행에 "다시 연락 필요". (24시간 넘게 미확인)
- **Given** 안 보낸 요청, **When** 엔지니어가 [보내기]를 누르고 상세 창에서 회신 요지를 적고 "회신 받음 표시"를 누르면, **Then** 줄이 "회신 받음"으로 흐려지고 회신 요지와 진행의 "회신 받음"이 보인다. (받는 담당자의 확인)
- **Given** 발송 실패한 요청, **When** 엔지니어가 열면 "발송 실패"와 [다시 보내기], 품질 담당이 열면 단추가 없다.
- **Given** 요청하기 창, **When** 적고 보내면, **Then** 예시 알림만, 요청 수 그대로. (요청하기 예시)

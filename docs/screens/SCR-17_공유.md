# SCR-17 판정 규칙: 목업과 다르게 만든 것 (공유)

| # | 목업 | 앱 | 이유 |
|---|---|---|---|
| 1 | 단위 탭(RFP 표기 → 표준 단위, kVA → MVA 환산 줄 포함) | 없음 | 단위 환산 금지(CR-10). 단위 사전도 DB에 없다 |
| 2 | 탭 수: 비교 방향 24 · 위험 표현 16 · 항목 이름 16 | 적재된 수 그대로 (비교 방향 39 · 위험 표현 10 · 항목 이름 33) | 실제 사전을 읽는다 |
| 3 | 비교 방향 칸: 비교 방식, 단위, 근거(IEC 번호), 수정자 | 표 · 번호, 시간 조건, 강점 방향 | 사전에 근거 규격·단위 칸이 없다. 이 사전은 RFP 표 번호마다 한 줄이라 표·번호를 보인다 |
| 4 | 위험 표현 칸: 강도(높음·보통), 자주 나오는 위치 | 언어, 위험으로 보는 조건 | 사전에 강도·위치 칸이 없다 |
| 5 | 마지막 수정 "10-22 · 사람 이름", 줄마다 수정자, 펼친 줄의 수정 이력 | "기록 없음", 수정 칸 없음, "수정 이력을 저장하지 않습니다" | 규칙 수정 이력을 저장하지 않는다. 고치기는 `data/seed`로 한다 |
| 6 | "이번 달 판정에 쓰임" | "지금 판정에 쓰임" (현재 판정 전체) | 판정에 날짜 칸이 없다 |
| 7 | 펼친 줄의 "이 규칙을 쓴 최근 판정" 검토 목록 | "이 규칙의 내용"(표준 항목, 처리 메모, 강점 방향) | 규칙별 판정 목록 API를 만들지 않았다. 쓴 수는 표에 있다 |
| 8 | 수정 요청 단추가 눌림 | 잠김 | 수정 요청을 받을 곳이 없다 |
| 9 | 사람이 제안한 표현 3줄(실제 사람 이름) | 예시 띠 + 역할 이름 | 제안·반영 흐름은 이 change 범위 밖. 정답지·채점 화면도 아직 없어 연결은 눌리지 않음 |

## 팀에 알릴 것

- 개발 DB의 RFP는 표 이름(TS-115-GIS)은 사전과 같지만 항목 번호가 달라서, 비교 방향 사전 줄이 한 번도 쓰이지 않았다(쓴 판정 모두 0). 판정은 항목 기본 방향으로 돌아간다. 사전은 원래 RFP 파일의 표 번호에 맞춰져 있다.
